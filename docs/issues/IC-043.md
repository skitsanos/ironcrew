# IC-043 — Non-dialog execution accepts blank final model replies as success

## Finding

The task executor, shared agent-turn helper, streaming conversation path, and
collaborative synthesis reject missing content but accept empty or whitespace-only
final content. Collaborative participant turns also turn missing content into
an empty contribution. A task can therefore publish a successful empty result
that its dependents consume. Conversation history can record an empty assistant turn.
The dialog-specific fix in [IC-042](./IC-042.md) does not cover these paths.

Evidence: `src/engine/executor.rs`, `src/lua/agent_turn.rs`,
`src/lua/conversation.rs`, and `src/engine/collaborative.rs`. Inspecting
`src/engine/task_runner.rs` also shows that an ordinary new error would enter
the configured full-task retry loop, potentially replaying completed tools.

## Outcome and validation

**Resolved locally on 2026-09-20.** The shared
`src/llm/final_response.rs::require_final_content` guard rejects missing,
empty, and whitespace-only finals through a typed `EmptyProviderResponse`
error. The executor, shared agent-turn helper, streaming conversation path,
and collaborative participant/synthesis paths use it. The task retry loop
does not replay this error; other errors retain their existing retry behavior.
Explicit `on_error` recovery remains available. Tool-call messages and
IC-042's graceful dialog stop behavior are unchanged.

The original acceptance contract was:

- Apply one shared final-content contract to non-dialog provider consumers:
  missing, empty, and whitespace-only final replies fail explicitly; nonblank
  content retains its original whitespace and reasoning remains separate.
- Do not reject tool-call messages merely because their text is absent or blank.
  Cover valid tool rounds followed by blank final replies.
- Do not automatically replay an entire task after this failure, even with
  `max_retries` configured. Previously executed tools cannot be rolled back.
  Explicit flow-level error handlers remain available.
- Failed replies must not publish a successful task result, admit dependent
  tasks, commit conversation history, advance its revision, or emit a completed
  conversation-turn event. Cover streaming and non-streaming paths.
- Preserve IC-042's distinct graceful `empty_response` dialog stop contract.
- Add deterministic mock-provider regressions, including call counts, history
  rollback, dependency gating, and a valid nonblank control. Update task and
  conversation documentation with the failure/retry boundary.

## Dependencies and boundaries

Package 1; no prerequisite. This is provider-final-content validation, not a
ban on intentional empty Lua/hook outputs, a provider retry redesign, or a
claim that prior tool side effects were undone. Usage accounting on failed
attempts belongs to [IC-046](./IC-046.md).
