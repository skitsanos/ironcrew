# IC-057 — Dependency audit fails because chrono is unmaintained

## Finding

Reproduced in hosted CI on 2026-11-20: after the lockfile refresh merged into
`develop`, `cargo audit --deny warnings` failed on one denied warning,
`RUSTSEC-2026-0543`, which reports `chrono` 0.4.45 as unmaintained. The
advisory names no vulnerability and has no patched version, so no lockfile
update clears it.

`chrono` is a direct dependency (`serde` feature only) and is also resolved
by `rmcp`. By reading `src/`: IronCrew uses it for `Utc::now().to_rfc3339()`
timestamps, RFC 3339 parsing of stored values, `Duration` arithmetic and one
`NaiveDate`. No known exposure follows from the advisory.

## Interim exception

`.cargo/audit.toml` ignores `RUSTSEC-2026-0543` only, with the review, the
exposure and the exit condition recorded beside the entry. A repository-policy
test fails if that file ignores any other advisory, or if the entry remains
after `chrono` leaves `Cargo.lock`. Review the exception again by 2026-12-20.

Validation on the change: `cargo audit --deny warnings` passes with the
exception and still fails without it; the repository-policy tests and the
issue registry check pass. No Rust code changed.

## Required outcome and acceptance

Remove IronCrew's direct use of `chrono` (for example by moving timestamps to
`jiff` or `time`) while keeping every stored and returned timestamp
byte-identical, with parity tests for formatting and parsing of the existing
forms. Then remove the exception once no resolved crate depends on `chrono`,
or record the remaining upstream dependent and keep the exception narrowed to
it. Close when the audit passes without the exception, or when the remaining
transitive use is reviewed and documented with a new review date.
