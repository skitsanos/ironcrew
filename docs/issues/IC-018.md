# IC-018 — Replica soak lacks retention-boundary steady-state evidence

## Required outcome and acceptance

The reviewed 150-second provider-free soak completed 253 runs and showed a
short local plateau, but its own report states that it did not cross a
long-duration storage steady state or cover provider, tool, conversation, and
large-result profiles. It therefore cannot establish bounded database, WAL,
vacuum, process-memory, or tail-latency behavior across journal retention.

Required outcome:

- run a 30–60 minute provider-free two-process PostgreSQL 15 profile across at
  least one configured journal-retention and prune boundary;
- record revision and binary hashes, exact workload/concurrency, pool and
  journal limits, relation growth, WAL, dead tuples, vacuum activity, readiness,
  process RSS, and operation latency distributions;
- declare pass/fail ceilings before the run for retained rows and bytes,
  post-prune growth, readiness failures, process RSS, and tail latency, then
  explain every exceeded ceiling rather than selecting a plateau afterward;
- prove logical caps, explicit replay gaps, bounded pruning, graceful cleanup,
  and stable tail behavior instead of extrapolating from the 150-second run;
- add separately identified bounded profiles for representative provider/tool,
  large-result, and owner-local conversation workloads without presenting mock
  or provider-free runs as live-provider evidence; and
- retain local-process, live-provider, Railway, and OpenShift results as distinct
  evidence classes with explicit cost and secret-handling boundaries.

Acceptance is a reproducible report with machine-readable evidence, not a claim
that one short host run predicts production steady state.
