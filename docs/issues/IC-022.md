# IC-022 — Shell tool leaks the process environment to model-controlled commands

## Finding

The opt-in `shell` tool spawns `sh -c <command>` in `src/tools/shell.rs` without
clearing or filtering the environment, so the child inherits the full parent
environment. `load_dotenv` (`src/cli/project.rs`) loads the project `.env` —
including `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and any other secrets — into the
process environment at startup. A prompt-injected agent with shell enabled can
therefore run `env` (or `printenv OPENAI_API_KEY`) and read every secret back
into its own context, defeating both the AGENTS.md "secrets never reach the
model" rule and the explicit `.env`-read denial enforced by
`validate_agent_read_path` (`src/tools/project_fs.rs`).

The correct pattern already exists for MCP stdio children in
`src/mcp/client_connect.rs`, which calls `env_clear()` and rebuilds a minimal
allowlisted environment (`SAFE_ENV_KEYS` plus `LC_*`, merged with explicit
config env). The `IRONCREW_ALLOW_SHELL` gate and the optional approval gate limit
*who* can enable shell, but neither prevents exfiltration once an approved or
allowed command executes.

## Outcome and validation

**Resolved on 2026-08-19.** The `shell` tool no longer inherits the process
environment. `src/tools/shell.rs` calls `env_clear()` and repopulates the child
from `src/tools/shell/environment.rs`, which keeps only `PATH`, `HOME`, `USER`,
`LANG`, `TZ`, `TERM`, and `LC_*`. Operators can add exact variable names through
`IRONCREW_SHELL_ENV_PASSTHROUGH`; that list can never re-admit an `IRONCREW_*`
name, so store URLs, API tokens, and HITL key material stay out of the child
regardless of configuration.

Regression coverage: an end-to-end test seeds `OPENAI_API_KEY` in the parent
process, runs a real shell command that echoes the variable and greps `env` for
it, and asserts the value never appears in the output; a companion test asserts
`PATH` survives so commands still run. Unit tests cover provider-key exclusion,
locale passthrough, exact-name matching (a `BUILD` entry does not admit
`BUILD_REGION`), and the `IRONCREW_*` re-admission block.

Documentation: `docs/tools.md` gains an "Environment isolation" section and
`docs/cli.md` documents `IRONCREW_SHELL_ENV_PASSTHROUGH`.

Validation: `cargo test --all-targets` (55 binaries, 0 failures), clippy clean,
`cargo fmt --check` clean.

Boundary: this stops secret exfiltration through the environment. It does not
sandbox the filesystem or network reachable from a shell command — `shell`
remains opt-in behind `IRONCREW_ALLOW_SHELL` and should stay approval-gated.
