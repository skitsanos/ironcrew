# IC-010 — Execution and storage metrics are incomplete

## Required outcome and acceptance

IronCrew already exposes a protected Prometheus `/metrics` endpoint with fixed,
low-cardinality labels for process active/limit gauges, principal admission,
idempotency quota rejections, and store-backed durable-ledger utilization.
What remains missing is execution and store-health coverage: operators cannot
alert directly on lease loss, reconciliation, storage failures, run/task/tool
outcomes and duration, provider/token trends, or terminal persistence failures
without parsing logs or polling records.

Required outcome:

- extend the existing authenticated endpoint without changing its bounded-label
  and fail-closed store-snapshot contract;
- instrument run/task/tool/provider outcomes and durations, SSE use, lease loss,
  reconciliation, terminal persistence, and store failures;
- keep labels to bounded vocabularies and prohibit run IDs, arbitrary flow/task
  names, URLs, errors, prompts, context, provider output, and secrets;
- make publication non-blocking and outside correctness-critical transitions;
- document new series/reset semantics, Railway/OpenShift replica aggregation,
  and a small alert set; and
- add label-cardinality, redaction, concurrency, failure-path, and existing
  endpoint-compatibility regressions.

Bundled dashboards, billing, high-cardinality per-run labels, and a hosted
telemetry backend are outside this extension.

## Progress checkpoint

On 2026-08-08, the protected Prometheus surface gained two readiness-critical,
unlabeled per-process gauges:

- `ironcrew_store_maintenance_healthy` exposes the latest complete
  heartbeat-plus-reconciliation outcome as `1` or `0`;
- `ironcrew_process_terminal_persistence_degraded_finalizers` exposes the
  current number of run or conversation finalizers retrying durable
  persistence.

Both reset with the process and use no caller-controlled labels. Store-backed
and real-process regressions passed authentication, `no-store`, existing-series
compatibility, exact HELP/TYPE/sample output, one-sample cardinality, secret and
principal omission, unhealthy/degraded values, and recovery back to `1`/`0`.
Railway/OpenShift guidance now distinguishes per-pod scraping and aggregation.

IC-010 remains in progress. Run/task/tool/provider outcomes and durations,
token trends, SSE use, lease loss/reconciliation counters, and broader storage
failure instrumentation still require bounded implementation and failure-path
coverage.
