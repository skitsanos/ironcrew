# IC-010 — Execution and storage metrics are incomplete

## Outcome and validation

At discovery, IronCrew exposed a protected Prometheus `/metrics` endpoint with
fixed, low-cardinality labels for process active/limit gauges, principal
admission, idempotency quota rejections, and store-backed durable-ledger
utilization. Execution and store-health coverage was missing: operators could
not alert directly on lease loss, reconciliation, storage failures,
run/task/tool outcomes and duration, provider/token trends, or terminal
persistence failures without parsing logs or polling records. The
resolved implementation below addresses that finding.

Required outcome:

- extend the existing authenticated endpoint without changing its bounded-label
  and fail-closed store-snapshot contract;
- instrument run/task/tool/provider outcomes and durations, SSE use, lease loss,
  reconciliation, terminal persistence, and store failures;
- keep labels to bounded vocabularies and prohibit run IDs, arbitrary flow/task
  names, URLs, errors, prompts, context, provider output, and secrets;
- make publication non-blocking and outside correctness-critical transitions;
- document new series/reset semantics, Railway/OpenShift replica aggregation,
  and a small alert set; and
- add label-cardinality, redaction, concurrency, failure-path, and existing
  endpoint-compatibility regressions.

Bundled dashboards, billing, high-cardinality per-run labels, and a hosted
telemetry backend are outside this extension.

## Implementation and evidence — 2026-08-11

The protected Prometheus endpoint now appends fixed-cardinality execution and
storage instrumentation after the authenticated durable snapshot succeeds. It
preserves the existing bearer-authentication, `Cache-Control: no-store`, exact
earlier HELP/TYPE/sample output, and fail-closed `503` behavior when the durable
snapshot cannot be read. A snapshot failure is counted as
`operation="metrics_snapshot"` for a later successful scrape.

The implementation adds the following exact families and closed labels:

| Coverage | Series and label vocabulary |
|---|---|
| Runs | `ironcrew_runs_total`, `ironcrew_run_duration_seconds`; `outcome`: `success`, `partial_failure`, `failed`, `aborted`, `timed_out`, `abandoned` |
| Tasks | `ironcrew_tasks_total`, `ironcrew_task_duration_seconds`; `outcome`: `success`, `error`, `skipped`, `cancelled` |
| Tools | `ironcrew_tool_calls_total`, `ironcrew_tool_call_duration_seconds`; `outcome`: `success`, `error`, `cancelled` |
| Providers | `ironcrew_provider_requests_total`, `ironcrew_provider_request_duration_seconds`; `provider`: `openai`, `openai_responses`, `anthropic`, `other`; `operation`: `chat`, `chat_with_tools`, `chat_stream`; `outcome`: `success`, `error`, `cancelled` |
| Tokens | `ironcrew_provider_tokens_total`; the same `provider` vocabulary and `type`: `prompt`, `completion`, `cached` |
| SSE | `ironcrew_sse_connections_total`; `scope`: `run_process`, `run_shared`, `conversation_process`; `outcome`: `accepted`, `limited` |
| Leases | `ironcrew_lease_losses_total`; `scope`: `run`, `conversation` |
| Reconciliation | `ironcrew_reconciliation_cycles_total`; `outcome`: `success`, `error`; and unlabeled `ironcrew_reconciliation_records_total` |
| Terminal persistence | `ironcrew_terminal_persistence_total`; `scope`: `run_record`, `run_idempotency`, `run_indeterminate`, `conversation_commit`, `conversation_indeterminate`; `outcome`: `success`, `error`, `fenced` |
| Store failures | `ironcrew_store_failures_total`; `operation`: `metrics_snapshot`, `readiness`, `maintenance_heartbeat`, `reconciliation`, `lease_heartbeat`, `terminal_persistence`, `event_append`, `event_read`, `audit`, `run`, `idempotency`, `conversation`, `human_input` |

The earlier unlabeled `ironcrew_store_maintenance_healthy` and
`ironcrew_process_terminal_persistence_degraded_finalizers` gauges remain
unchanged. All new counter and histogram cells are in-memory, process-local,
saturating atomics and reset at process start. Duration histograms use fixed
cumulative buckets from 5 ms through 300 seconds plus `+Inf`. Reconciliation
can bulk-count abandoned runs without inventing elapsed time, so the abandoned
run counter can exceed its histogram count; skipped tasks record zero duration.
Provider tokens advance only from usage returned by a successful provider
response and are not billing evidence. Third-party `LlmProvider`
implementations default to the fixed `other` family; an implementation can
select another fixed family explicitly. OpenAI-compatible endpoints configured
through the built-in OpenAI provider remain `openai`.

Recording happens outside correctness-critical transitions. Dropped
in-flight task attempts and instrumented tool or provider futures use the fixed
`cancelled` outcome; instrumented storage errors increment an operation bucket
without copying an error into the metric surface. Run IDs, principals,
flow/task/tool names, URLs, errors, prompts, context, provider output, tokens,
and secrets cannot become labels.

Focused regressions cover closed vocabularies and exact sample cardinality,
secret/caller-value omission, cumulative histogram monotonicity during
concurrent record/scrape races, provider token aggregation, concurrent
recording without lost increments, cancellation and error outcomes,
durationless reconciled runs, authenticated endpoint compatibility, and the
existing durable snapshot boundary.

Final validation passed:

- `cargo fmt --all -- --check`;
- `cargo clippy --all-targets -- -D warnings`;
- `cargo test --all-targets`, including 371 library tests, 378 binary tests,
  and the integration targets, with only the repository's intentional ignores;
- a disposable PostgreSQL 15.18 gate: 48 PostgreSQL-store tests, two
  multi-replica HTTP tests, and ten separate-process replica tests;
- a bounded two-process PostgreSQL soak with two successful runs, exact 16/16
  receiver distribution across 32 capability probes, no failed runs or
  deadlocks, and clean disposal of the dedicated database container; and
- the issue registry, repository-policy, Lua-example, crew-contract, dependency
  audit, and worktree checks.

The REST, CLI, cloud, and multi-replica contracts now document per-pod scraping,
sum-of-rates and histogram-bucket aggregation, shared-snapshot deduplication,
and a small operator-actionable alert set for readiness, durability, provider
quality, and capacity. This work intentionally does not supply a hosted
telemetry backend, dashboard, long-term metrics store, billing calculation, or
high-cardinality labels.

IC-010 is resolved. This is implementation, local regression, disposable
PostgreSQL, and bounded separate-process evidence. It does not claim a hosted
metrics backend, a deployed Railway/OpenShift scraper, a production alert
policy, or a published release.
