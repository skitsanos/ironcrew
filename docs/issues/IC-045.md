# IC-045 — Validate does not evaluate crew construction without effects

## Finding

`cmd_validate` in `src/cli/commands.rs` checks project declarations but only
compiles `crew.lua` with `into_function()`. Inline constructors, unknown keys,
model option combinations, and dynamically assembled dependency graphs are
not exercised. [IC-028](./IC-028.md) deliberately left no-effect evaluation
as follow-on work; its runtime unknown-key fix remains resolved.

## Required outcome and acceptance

- Add a documented bounded construction-evaluation mode to `ironcrew validate`
  using the real constructors/parsers and [IC-044](./IC-044.md) capability rules.
- Validate evaluated agent/task/dialog/conversation options and constructed
  dependency graphs, including unknown references and cycles, before paid work.
- Prevent provider requests, network access, database effects, process spawning,
  file writes, and execution-triggered side effects throughout project loading
  and evaluation, including config files, imports, callbacks, and nested flows.
  Bound CPU/instructions, memory, recursion, and permitted project reads.
- Do not fabricate successful execution results to drive unknown branches.
  Report unsupported effect-dependent construction or unvalidated paths
  explicitly; define exit statuses so CI cannot mistake partial validation for
  complete validation. Document the limit of inspecting dynamic Lua.
- Cover misspelled keys, unsupported effort/model combinations, invalid graphs,
  infinite loops, effect attempts, and an ordinary valid project. Assert no
  external calls or writes occur, including on error and cancellation.
- Integrate the appropriate mode into example/CI validation and reconcile CLI
  help, workflow docs, and example expectations.

## Dependencies and boundaries

Package 2, depends on IC-044. This validates construction, not provider behavior,
task output quality, every possible Lua branch, or deployed runtime behavior.
The existing static checks must not be represented as stronger evidence.

## Validation plan

Use adversarial sandbox and process-level CLI regressions, full Rust and
repository gates, and the Lua example gate. Run security/dependency checks when
the sandbox changes. Record unsupported construction patterns explicitly.
