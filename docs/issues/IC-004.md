# IC-004 — One-second run leases have no heartbeat safety margin

## Outcome and validation

**Resolved locally on 2026-08-07.** Production environment parsing now accepts
`IRONCREW_RUN_LEASE_TTL_SECONDS=6..86400` (default 60) and rejects 1–5 with an
actionable safety-margin error. Explicit `RunLeaseConfig` construction still
allows shorter positive leases for deterministic unit/store fixtures without
weakening server configuration.

Owner heartbeats and replica maintenance share the `TTL / 3` cadence. At the
six-second minimum that is two seconds; each maintenance operation has a 666 ms
outer watchdog and a 532 ms per-statement PostgreSQL timeout. The initial fence
plus scheduled renewals therefore leaves recovery space after a missed tick,
while the documented detection window remains lease expiry plus cadence and
bounded maintenance work when the run fits in the next 64-row batch.

Parser/formula boundary tests cover 5 rejection, 6 and 86400 acceptance, 86401
rejection, and a three-second explicit test lease. Against disposable
PostgreSQL 15, the real process gate waits for a fresh six-second lease,
confirms the owner is stopped with `waitpid(WUNTRACED)`, misses two two-second
heartbeat opportunities for 4.25 seconds without a peer false-abandonment,
then requires a strictly newer deadline after `SIGCONT`. A later real
`SIGKILL` is reconciled to `Abandoned` by the survivor. The final target passed
1/1 in 24.36 seconds. This is local Linux/PostgreSQL timing evidence; deployed
Railway and OpenShift scheduling/routing remain separate gates.
