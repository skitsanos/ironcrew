# IC-027 — Secret-bearing custom headers survive cross-host redirects

## Finding

reqwest's redirect handling strips only a fixed set of sensitive headers
(`Authorization`, `Cookie`, `Proxy-Authorization`, and similar) on cross-host
hops. Two egress paths in scope carry secrets in *custom* headers that are not on
that list:

- `http_request` writes its `api_key` auth into an arbitrary header (default
  `X-API-Key`) and forwards any model- or Lua-supplied `headers` entries
  (`src/tools/http_request/request.rs`).
- The Anthropic provider sends the API key in `x-api-key`
  (`src/llm/anthropic.rs`).

The redirect policy (`src/utils/network.rs`) validates that each hop targets a
public address but follows up to 10 hops to any public host. A malicious or
compromised endpoint (or, for the tool, a model-chosen URL) can therefore respond
with a 302 to an attacker-controlled host and collect the secret header. MCP
already avoids this by using a no-redirect client
(`secure_no_redirect_client`); these two paths do not.

## Outcome and validation

**Resolved on 2026-08-19.** Requests carrying a secret in a custom header no
longer follow a redirect off their origin.
`same_origin_redirect_policy` (`src/utils/network.rs`) keeps the existing SSRF
validation and hop limit, and additionally requires each hop to match the
original scheme, host, and port.

`http_request` selects a client per request
(`src/tools/http_request/redirect_policy.rs`): calls with `auth_type` or any
caller-supplied `headers` use the same-origin clients, while plain requests keep
the normal redirect behavior. The Anthropic provider, which sends `x-api-key` on
every request, uses the same-origin policy unconditionally.

Regression coverage: a test stands up two local servers, has the first 302 to
the second, and asserts the destination never observes an `x-api-key` header and
that the call fails as a redirect error. A positive control asserts a
same-origin redirect is still followed and returns the final body, so the fix
does not over-restrict. A unit test pins the credential-detection rule
(`auth_type`/`headers` present; `none` and empty headers excluded).

Validation: `cargo test --all-targets` (55 binaries, 0 failures), clippy clean.

Boundary: MCP already used a no-redirect client and is unchanged. Non-credential
`http_request` calls keep following cross-host redirects, which is the behavior
callers expect for plain fetches.
