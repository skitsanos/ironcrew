# IC-039 — Build context, dev-dependency comment, and client material housekeeping

## Finding

Three low-risk hygiene items in the build and repository layout:

- The root `Dockerfile` copies all of `examples` and `tests` into the build
  context before the single `cargo build --release --locked`, so every docs or
  example edit invalidates the compile layer. Correction to the original audit
  note: `examples/` is **not** entirely inert — `src/cli` embeds
  `examples/graph-prototype/assets` via `include_str!`, so that subtree is a
  real build input and removing it breaks the build. Only the remainder of
  `examples/` and all of `tests/` are unnecessary. There is also no
  dependency-caching stage despite `Cargo.lock` being copied first.
- The `sqlx` dev-dependency comment in `Cargo.toml` says it is "used only by the
  gated `postgres_store_test`", but `tests/multi_replica_http_test.rs` and
  `tests/two_process_replica_acceptance_test.rs` (plus its phase modules) also use
  it. All are `#![cfg(feature = "postgres")]`-gated and `postgres` is a default
  feature that already activates the optional main dependency, so the
  unconditional dev-dependency mainly forces `sqlx` to compile under
  `--no-default-features`.
- `examples/clients/` holds real-client-named material and a zip archive. It is
  git-ignored and docker-ignored, so nothing leaks into the repository or images
  today, but client-identifiable content inside the product tree is one
  `git add -f` away from publication.

## Outcome and validation

**Resolved on 2026-08-19.** All three hygiene items are addressed.

The root `Dockerfile` no longer copies `tests/`, and copies only
`examples/graph-prototype/assets` rather than the whole `examples/` tree. This
correction matters: contrary to the original audit note, `examples/` is *not*
inert — `src/cli` embeds the graph viewer assets with `include_str!`, and a
build without them fails. Verified by building the image (which failed with the
over-broad removal, then succeeded with the narrowed copy) and running
`ironcrew --version` from the resulting image; the test image was removed
afterwards.

The `sqlx` dev-dependency comment in `Cargo.toml` now names all the gated
suites that use it (`postgres_store_test`, `multi_replica_http_test`,
`two_process_replica_acceptance` and its phase modules) and records why it is
declared unconditionally: the gated suites must still compile when the
`postgres` feature is off. `cargo build --no-default-features` succeeds.

`examples/clients/` is left in place and remains git-ignored and docker-ignored;
relocating client-named material outside the repository tree is recorded here as
the owner's decision to make, not an automated change.

Validation: Docker image builds and runs; `cargo build --no-default-features`
succeeds; `cargo test --all-targets` (55 binaries, 0 failures).

Boundary: no dependency-caching build stage was added — that is a build-time
optimization, separate from the correctness of the build context.
