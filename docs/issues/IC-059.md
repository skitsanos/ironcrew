# IC-059 — Pre-push gate outlives the SSH push session, so a passing gate cannot complete the push

## Finding

Reproduced on 2026-11-20. `.githooks/pre-push` ran the complete
`scripts/pre-push-check.sh` inside `git push` (about 30 to 40 minutes with the
PostgreSQL floor and latest suites, the replica soak and the release build).
Over SSH the gate finished with `every locally reproducible CI gate passed`,
then `git push` exited 141 (SIGPIPE): the hosting provider had closed the idle
SSH session while the hook ran, so no pack was sent and the branch was not on
the remote. The same push over stateless HTTPS succeeded, but only after a
second full gate run.

Boundary: the hook failed closed and nothing unvalidated was pushed. The
defect is that the documented push path could not succeed over SSH, and every
retry repeated the whole gate.

## Outcome and validation

- Running the gate is now separate from pushing. `scripts/pre-push-check.sh`
  captures the clean `HEAD` tree and start time before the latest-stable
  refresh, and after every check and the unchanged-worktree comparison it runs
  `scripts/gate_receipt.ts write`. The writer requires a clean worktree whose
  `HEAD` tree equals the start tree, so a commit made during the run fails the
  gate instead of receiving a receipt. The receipt
  (`{version, tree, commit, started, completed}`) is written atomically with
  mode 0600 to `ironcrew-gate-receipt.json` in the worktree's own Git
  directory: never tracked, kept by `cargo clean`, separate per worktree.
- `.githooks/pre-push` no longer runs the gate. It runs
  `scripts/gate_receipt.ts verify-push`, which parses git's pre-push input and
  accepts the push only when a readable receipt, at most
  `IRONCREW_GATE_RECEIPT_MAX_AGE_SECONDS` old (default 86400; malformed values
  fail closed), validated the tree of every pushed ref, tags included.
  Deletion-only pushes need no receipt. Binding to the tree keeps a
  message-only amend and rejects any content change. Missing, stale,
  future-dated, oversized or malformed receipts block with the command to run.
- Fallback decision: the hook never runs the gate itself. An automatic
  fallback would reproduce this failure after another 30 to 40 minutes;
  running `./scripts/pre-push-check.sh` (or `task pre-push`) first is the only
  path. The gate's checks are unchanged. The receipt is a local workflow guard,
  not a security boundary: hosted CI remains authoritative.
- `AGENTS.md`, the check and release skills (including tag pushes) and
  `task pre-push` describe the order: commit, run the gate, push.
- Regressions: `scripts/tests/gate_receipt.test.ts` covers parsing, tree
  binding, a commit during the run, dirty trees, amends, missing, stale,
  future-dated and unreadable receipts, mixed-tree and tag pushes, and real
  `git push` runs of the tracked hook against a disposable bare remote.
- Focused validation: `bun test scripts/tests/*.test.ts`,
  `python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'`,
  `bun run scripts/validate_skills.ts`, `bun run scripts/issues_registry.ts
  check`, `actionlint` and `bash -n` on the hook and gate. The complete gate
  run that recorded a receipt for this change, and the hook accepting that tree
  and refusing a different one against a local bare remote, are recorded on
  the pull request.
