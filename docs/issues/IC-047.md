# IC-047 — Runs lack a shared token budget across provider requests

## Finding

Per-request `max_tokens`, tool-round caps, timeouts, and history limits do not
bound aggregate tokens consumed by a run. Parallel tasks, retries, dialogs,
foreach expansion, agent delegation, and subflows can each initiate billable
provider requests without a shared token-admission contract.

Evidence: `src/engine/agent.rs`, `src/engine/executor.rs`,
`src/engine/task_runner.rs`, and the conversation/dialog provider loops.

## Outcome and validation

**Resolved locally on 2026-09-21.** Provider calls now share atomic token
admission, rather than relying on independent request limits or counting usage
only after dispatch. IC-046's existing uncommitted checked-accounting work is
preserved. The public contract is in [run token budgets](../token-budgets.md).

- `IRONCREW_MAX_RUN_TOKENS` is opt-in: unset means explicitly `disabled`;
  enabled values must be decimal integers from 1 through 1,000,000,000.
  CLI/server startup and embedded scope creation reject invalid configuration.
  Lua flow configuration cannot replace the operator's shared budget.
- Native OpenAI Responses without provider-hosted tools is the initial
  supported admission contract. The exact input-token endpoint counts the
  generation payload's input-bearing fields. Admission reserves that count
  plus the explicit all-output bound, defaulting to 4,096 output tokens only
  when no bound was supplied. Unsupported providers, proxy origins, hosted
  tools and mutable input references fail closed before generation. Custom
  Rust providers must explicitly own both admission and checked receipts.
- Retries, parallel/foreach tasks, dialogs, delegated agents, repeated crews
  and nested Lua flows inherit one process-local budget. Standalone HTTP
  conversation messages get independent per-request budgets; restored session
  receipts do not consume them until history is sent as new model input.
- Complete bounded receipts release unused reservations. Missing/partial
  receipts and cancellation conservatively retain their full bound. Denial,
  counting failure and provider-bound violations prevent further dispatch.
  Overruns remain visible as actual receipts, not clamped billing totals.
- Budget failures are non-retriable, propagate through CLI/Lua/HTTP execution,
  and cannot become successful run output just because Lua catches an error.
  Checked task/run snapshots, events, history and JSON/SQLite/PostgreSQL records
  retain budget state. HTTP messages expose `request_usage`, budget errors
  return HTTP 422, and successful keyed replay preserves the original snapshot.
- The checked snapshot wire contract now requires `budget`. Pre-budget
  snapshots are unsupported; no legacy conversion or automatic rewriting of
  user history was introduced. Capacity accounting is distinct from billed
  usage, not a currency guarantee or a cross-run/distributed account quota.
  In-flight reservations are not a durable restart/failover journal.

### Original acceptance criteria

- Introduce an operator-controlled run token ceiling, proposed as
  `IRONCREW_MAX_RUN_TOKENS`, with documented units, default, hard maximum, invalid
  configuration handling, and precedence. Flow configuration cannot raise the
  operator ceiling. Make any disabled-budget state explicit.
- Share one budget identity across all work belonging to a run, including
  retries, tools' agent calls, foreach tasks, dialogs, and nested flows. Define
  the equivalent scope for standalone HTTP conversation requests/sessions.
- Use atomic pre-dispatch admission/reservations and receipt reconciliation;
  a post-response counter alone is insufficient for concurrent requests.
  Define conservative input/output accounting and refuse unsupported bounded
  admission rather than silently making a hard-cap guarantee that cannot hold.
- Handle partial/missing usage, cancellation, failed attempts, and in-flight
  reservations without resetting or refunding potentially billed consumption.
- Exhaustion must block new provider calls, terminate coherently, and appear in
  CLI/Lua/HTTP status, events, and persisted records without success-shaped output.
- Test boundary exhaustion, concurrent admission, nested work, retries,
  cancellation, missing receipts, and independent runs. Document ownership and
  replica constraints without claiming failover or exact global billing control.

## Dependencies and boundaries

Package 3, depends on [IC-046](./IC-046.md). A token budget is not an exact
currency ceiling: provider pricing, input accounting, and already-dispatched
requests constrain the guarantee. State the enforced limit and any bounded
overrun explicitly. Monetary estimates must be labeled separately.
