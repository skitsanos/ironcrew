# IC-009 — Crew effectiveness evidence is too small for product claims

## Required outcome and acceptance

The current live-provider receipt is a useful smoke: three synthetic cases,
one GPT-4.1 repetition, and exact deterministic scoring show better evidence
completeness for DAG/collaborative crews at substantially higher token and
latency cost. It cannot establish statistical reliability, model generality,
domain transfer, or return on cost. Contract mode is oracle-backed and is not
effectiveness evidence.

Required outcome:

- run the complete six-case corpus with predeclared thresholds and enough
  repetitions to report uncertainty, paired wins/ties/losses, cost, and latency;
- add at least two representative domain packs derived from real intended use,
  with versioned inputs and deterministic or independently reviewed oracles;
- compare single-call, deterministic DAG, and collaborative variants under the
  same model/settings and randomized order;
- record failures, parse/schema validity, token/cached-token usage, latency,
  revision, binary/dataset hashes, and provider/model identity; and
- define when the simpler workflow wins so the benchmark guides topology choice
  rather than merely marketing crews.

Acceptance is an honest reproducible report, not a requirement that every crew
variant win. Provider cost and rate limits must remain bounded before execution.
