# IC-040 — postgres_store.rs needs domain decomposition

## Finding

`src/engine/postgres_store.rs` is roughly 8,800 lines: a ~3,300-line
`impl PostgresStore` inherent block (schema bootstrap, connection/version
handling, and every table-focused helper) followed by a ~5,100-line
`impl StateStore for PostgresStore` block, together spanning 79
`async fn`s. It is the single largest production module in the tree by a
wide margin and is carried today as a reviewed exception in
`scripts/module_size_policy.json` (`max_lines: 8808`) rather than split.

IC-011's resolution added the growth ratchet — `scripts/check_module_size.py`
plus the exception-budget policy that stops oversized modules from growing
further unreviewed — it deliberately did not shred this module. That
decomposition was scoped out as follow-up work at the time.

The `feature/postgres-app-data` branch's Task 1 extracted
`src/engine/pg_runtime.rs` (pool builder, bounded retry/backoff,
connect-timeout parsing) out of `postgres_store.rs` so the new `postgres.*`
app-data capability (`src/engine/app_db/`) could share connection-setup code
without depending on `postgres_store.rs`'s fencing, idempotency, HITL, and
journal logic. That extraction is useful groundwork — it is the only code the
new capability reuses from the store — but it removed only a small,
self-contained slice. The bulk of the module — run history, run
events/journal, idempotency, conversations, HITL mailbox, audit, and
lease/maintenance logic — remains one undivided file.

## Required outcome and acceptance

Decompose `postgres_store.rs` domain-by-domain into `src/engine/postgres_store/`
child modules, matching the eight domains identified in the design spec
(`docs/superpowers/specs/2026-08-19-postgres-app-data-design.md`, §11):

1. row decoding / codecs
2. run history
3. run events / SSE journal
4. idempotency
5. conversations
6. HITL mailbox
7. audit
8. leases / maintenance

Each domain is its own pass behind the full acceptance gates (`cargo fmt
--check`, zero-warning `cargo clippy --all-targets`, all-green `cargo test
--all-targets`, `cargo build --no-default-features`, and
`python3 scripts/check_module_size.py`) — do not attempt the whole module in
one change. A pass that retires or shrinks the `postgres_store.rs` exception
must ratchet the corresponding entry in `scripts/module_size_policy.json`.
Retiring the exception entirely must also reduce `MAX_EXCEPTION_BUDGET` in
`scripts/check_module_size.py`, since the checker enforces the budget as an
exact match (currently `48`) with the policy's exception count. Do not change
the `StateStore` trait's public contract as part of this decomposition; this
is an internal reorganization, not a behavior change.

## Outcome and validation

The eight specified PostgreSQL store domains now live in focused
`src/engine/postgres_store/` modules. The final pass keeps public `StateStore`
behavior unchanged while making connection construction, schema lifecycle,
lease maintenance, and cancellation independently reviewable. No compatibility
path or storage migration was removed; the existing PostgreSQL 15 bootstrap
continues to heal and verify older supported schemas atomically.
