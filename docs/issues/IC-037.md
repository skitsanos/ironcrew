# IC-037 — Provider scaffolding is triplicated and RateLimiter::new can panic

## Finding

`RateLimiter::new` computes `std::time::Instant::now() - Duration::from_secs(60)`
in all three providers (`src/llm/openai.rs`, `src/llm/anthropic.rs`,
`src/llm/openai_responses.rs`). `Instant` subtraction panics on underflow, so on
a platform whose monotonic clock starts near zero (fresh boot or VM), constructing
a provider panics.

The same three files carry copy-pasted scaffolding: an identical `RateLimiter`,
the non-success error-body handling, usage parsing, and the SSE line-loop
skeleton. That duplication is why IC-033 (fixed timeout) and IC-034 (status lost
before JSON parse) each need the same fix applied three times.

Related latent defect: all three streaming paths accumulate tool calls in a
`HashMap` and assemble via `into_values()`, losing provider emission order
(`src/llm/openai.rs`, `src/llm/anthropic.rs`, `src/llm/openai_responses.rs`). In
`src/llm/openai.rs` the function name is captured only inside the branch that
sees a non-empty `id`, so a compatible server sending name and id in separate
deltas yields a buffer that the completeness filter silently drops. Both
executors currently force non-streaming when tools are present, so this is
dormant — but the code emits `ToolCallStart`/`Delta` chunks as if it worked.

## Required outcome and acceptance

Provider construction must not panic on a young monotonic clock: use
`checked_sub` or an `Option<Instant>`. Extract the shared rate limiter, error-body
reader, and SSE stream skeleton into one module (for example `src/llm/common.rs`)
so timeout and status-handling fixes apply once. Make streaming tool-call
assembly deterministic by keying on index in an ordered map, capture the function
name independently of the id, and surface incomplete buffers as an error rather
than filtering them away. Add regression coverage for the clock edge case and for
ordered, complete streaming tool-call assembly.

### Status note — 2026-08-19

Partially addressed. The panic is fixed: all three providers now build their
rate limiter with `Instant::now().checked_sub(...)` and fall back to the current
instant, so construction cannot underflow on a young monotonic clock.

The remaining work — extracting the shared rate limiter, error-body reader, and
SSE stream skeleton into one module, and making streaming tool-call assembly
ordered and complete — is deliberately still open. It is the right home for the
configurable provider timeout in [IC-033](./IC-033.md) and the SSE field-form
parsing nit noted in [IC-034](./IC-034.md), so those three should be done
together rather than triplicating another fix.
