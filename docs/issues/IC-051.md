# IC-051 — Renovate refreshes the release base image without its receipt digest

## Finding

The release workflow records the Wolfi base image as `BASE_IMAGE_REFERENCE` and
`BASE_IMAGE_INDEX_DIGEST` in `.github/workflows/release.yml`. Signed release
receipts describe the image through those values, and repository policy
requires them to equal the `FROM` pin in `docker/runtime.Dockerfile`.

Renovate managed only the Dockerfile pin. Each Wolfi digest refresh moved the
`FROM` line and left the workflow digest behind, which failed the Repository
policy job. This happened on the refresh merged as `0a3d862` (#113) and again
on [#121](https://github.com/skitsanos/ironcrew/pull/121). Both times the
workflow digest had to be aligned by hand (`0a3d862`, `0607e9c`). Wolfi's
moving index makes this a recurring failure.

## Required outcome and acceptance

- Make Renovate propose the workflow digest in the same grouped refresh as the
  Dockerfile pin, and resolve both through the same lookup so they cannot
  diverge.
- Keep the existing policy check that rejects a mismatch, and keep
  `Dockerfile`, `docker/runtime.Dockerfile`, and the IC-050 evidence exclusion
  unchanged.
- Add a regression that fails if the workflow pin stops being extracted, or if
  its lookup stops matching the Dockerfile's digest-only lookup.

## Outcome and validation

Resolved on 2026-10-07 with one regex custom manager in `renovate.json`. It
reads `BASE_IMAGE_REFERENCE` as `depName` and `BASE_IMAGE_INDEX_DIGEST` as
`currentDigest` from `.github/workflows/release.yml`, with the `docker`
datasource. It sets no `currentValue`, matching the Dockerfile's digest-only
`FROM`.

- Renovate 44.142.0, run under Node 24.21.0 with `--platform=local
  --dry-run=lookup` on a scratch worktree where both pins were rolled back to
  `sha256:9c2092b0…`, extracted `cgr.dev/chainguard/wolfi-base` from both files
  (`dockerfile` and `regex` managers). Both had `currentValue` null and the
  same `currentDigest`. Both proposed a `digest` update to
  `sha256:238642d4…` on the single `renovate/dependency-refresh` branch.
- Renovate's `doAutoReplace` rewrote each rolled-back file with one changed line.
  Both outputs were byte-identical to the committed `release.yml` and
  `runtime.Dockerfile`.
- In that Node 24 run, Renovate fell back to JavaScript `RegExp` because the
  installed RE2 binary targets Node 22. Under Node 22, Renovate's `regEx()`
  compiled the match string with RE2 and produced exactly one match with the
  expected `depName` and `currentDigest`.
- `renovate-config-validator --strict` accepted the repository config.
- `scripts/tests/release_base_image.test.ts` runs the committed match string
  against `release.yml`. Negative probes failed as intended: removing the
  custom manager, reshaping the env block so the pattern no longer matched, and
  adding a `currentValueTemplate`.
- Bun policy tests (62 tests, 585 assertions), repository Python tests (76), and
  the issue registry check passed. This change touches no Rust, workflow, or Lua
  source.

Boundary: this is local evidence against Renovate's own code. Hosted Renovate
reads repository configuration from the default branch, `main`, and
`useBaseBranchConfig` is unset. The custom manager is therefore inert until this
change reaches `main`. Until then, a Wolfi refresh still fails Repository policy
and needs the workflow digest aligned by hand. The first hosted refresh after
release that moves the Wolfi digest is the platform evidence.
