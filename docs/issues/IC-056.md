# IC-056 — Shared discovery deadline races Python startup in semantic MCP capability acceptance

## Finding

The semantic missing-tools-capability test shared a one-second discovery deadline with deliberate
timeout and caller-abort fixtures. A cold Python startup could exhaust that deadline before capability
validation, producing a timeout instead of the required semantic rejection on hosted macOS.

## Outcome and validation

The capability checks run in a separate integration-test process with a bounded ten-second functional
discovery budget and five-second shutdown budget. Both immediate and deliberately delayed startup
must reject the missing tools capability, send exactly one discovery request with no tools/list,
and reap the child process. The delayed startup exceeds the old one-second deadline deterministically.

`tests/mcp_stdio_capability_test.rs` contains both cases. Existing HTTP/stdio timeout and caller-abort
fixtures keep their one-second settings and behavior. Shared process-reaping assertions are reused;
production MCP timeouts, providers and protocols are unchanged. No ignored tests or lint suppressions
are introduced. This generic correction is preserved independently of the withdrawn proposal in
IC-055. Hosted macOS previously passed the original 35 boundary tests and both functional cases.
