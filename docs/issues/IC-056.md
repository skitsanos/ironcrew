# IC-056 — Shared discovery deadline races Python startup in semantic MCP capability acceptance

## Finding and scope

Hosted macOS job 121122749000 in [CI run 40177992704](https://github.com/skitsanos/ironcrew/actions/runs/40177992704)
at source `0815ad9` fails
`capability_negotiation_tests::stdio_without_tools_capability_fails_before_tools_list_wire`.
The assertion expects a missing-tools-capability rejection, but receives
`MCP stdio discovery timed out after 1 seconds`. The other 35 tests in that target pass.
Shared `boundary_test_support::isolate_environment` applies the one-second discovery deadline to
both semantic negotiation and deliberate timeout/cancellation fixtures. Starting a fresh Python
interpreter is therefore part of an unrelated semantic test's deadline. IC-049 covers a different
persisted SSE race; this cause is separate from IC-055's history-reader implementation.

## Required outcome and acceptance

Separate functional stdio capability acceptance from the short-deadline fixture process. Preserve
one-second timeout/caller-abort/process-group cleanup coverage and all production timeout behavior.
Do not silence, ignore or retry away the semantic assertion. Reproduce with controlled delayed
fixture startup, then verify no tools/list reaches the wire, exact capability rejection and child
reaping under a distinct bounded functional discovery budget. Avoid cross-test global environment
races by isolating the functional budget in a separate integration target/process.

Run required Rust/repository gates and exact-head hosted CI before final acceptance. Use only
hermetic stdio/loopback fixtures, no live providers or private records. Retain original history and
unknown checked usage; no production access, release or deployment is authorized.

## Outcome and validation

The exact completed macOS log and deterministic local control reproduce the race: introducing a
1.2-second interpreter startup delay under the old one-second budget produces a discovery timeout
before semantic validation. The corrected test lives in a separate integration-test process with a
ten-second functional deadline and a five-second shutdown deadline. Both immediate and delayed
startup cases require the missing-tools-capability error, exactly one `server/discover` request, no
`tools/list` request and child reaping.

Both cases pass five repeated local runs. The original boundary target passes all 35 tests. The
shared boundary settings and HTTP/stdio timeout/caller-abort test files remain byte-for-byte equal
to the original source. No production runtime deadline changes, suppressions or ignored tests are
introduced. Formatting, `cargo clippy --all-targets -- -D warnings` and the full default all-target
test matrix pass (1,572 passed, three intentional ignores, no failures). An independent read-only
acceptance review found no material issue in this correction.

The verification defect is resolved in source. The complete canonical pre-push gate, normal enabled
push hook and exact-head hosted/artifact qualification are required separately before accepting the
final candidate. Their final identities and results will be appended to the primary issue ledger and
workspace qualification receipt; this source outcome does not claim a deployment or release.
