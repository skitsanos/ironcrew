# IC-041 — No-default-features build regressed after provider HTTP extraction

## Finding

IronCrew documents `cargo build --no-default-features` as the supported build
for deployments that need neither MCP nor PostgreSQL. That build now fails with
`E0432` because `src/llm/provider_http.rs` imports `bytes::Bytes`
unconditionally while `Cargo.toml` declares `bytes` as optional and activates
it only through the default `mcp` feature.

The regression is present on the current `develop` baseline and is independent
of IC-036. IC-039's 2026-08-19 validation remains historical evidence that the
feature-minimal build passed when that issue closed; the later provider HTTP
extraction introduced a new unconditional consumer without adding a matching
feature-build gate to CI.

## Outcome and validation

**Resolved on 2026-09-19.** `bytes` is now an unconditional dependency because
the shared provider HTTP stream module is unconditional; the `mcp` feature no
longer owns it. PostgreSQL- and MCP-only helpers are compiled only with their
features, while shared backend result contracts retain narrowly scoped
feature-conditional dead-code annotations for variants that only a PostgreSQL
implementation can construct.

Protected CI now runs `cargo build --no-default-features` under the repository's
global `RUSTFLAGS=-Dwarnings`, and the repository-policy suite asserts that the
gate cannot be removed silently.

Local validation passed for warning-denied builds with no features,
PostgreSQL-only, and MCP-only; `cargo fmt --all -- --check`;
`cargo clippy --all-targets -- -D warnings`; `cargo test --all-targets`;
`cargo test --doc`; `cargo audit --deny warnings`; module-size and Python policy
tests; Bun policy and registry tests; `actionlint`; all Lua examples; and the
36-run crew-effectiveness contract smoke. The protected pull-request matrix
provides the final Linux, macOS, Windows, PostgreSQL 15, and release-build
evidence.
