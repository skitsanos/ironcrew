# IC-041 — No-default-features build regressed after provider HTTP extraction

## Finding

IronCrew documents `cargo build --no-default-features` as the supported build
for deployments that need neither MCP nor PostgreSQL. That build now fails with
`E0432` because `src/llm/provider_http.rs` imports `bytes::Bytes`
unconditionally while `Cargo.toml` declares `bytes` as optional and activates
it only through the default `mcp` feature.

The regression is present on the current `develop` baseline and is independent
of IC-036. IC-039's 2026-08-19 validation remains historical evidence that the
feature-minimal build passed when that issue closed; the later provider HTTP
extraction introduced a new unconditional consumer without adding a matching
feature-build gate to CI.

## Required outcome and acceptance

Restore the documented feature-minimal build without weakening the provider
streaming implementation. Make `bytes` available to the unconditional provider
HTTP module or remove that module's direct dependency on it, and add
`cargo build --no-default-features` to protected CI so the supported build mode
cannot silently regress again.

Acceptance requires `cargo build --no-default-features`, the default
`cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`, and the
repository-policy gates to pass together. Keep MCP and PostgreSQL optional; do
not solve the build by enabling either default feature implicitly.
