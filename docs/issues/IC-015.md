# IC-015 — Release automation admitted ambiguous tags and non-cascading Docker triggers

## Outcome and validation

**Resolved locally on 2026-08-07.** The release-source guard checked version
and `main` ancestry but accepted lightweight tags, while the release workflow
granted contents-write and OIDC authority to guard and build jobs. Published
verification guidance used a repository-prefix certificate regular expression,
and arbitrary tag annotations were transported through a fixed workflow-output
delimiter. Docker publication also listened for a release event that cannot be
caused by the preceding `GITHUB_TOKEN`-authenticated release action.

The guard now requires an annotated stable `vX.Y.Z` tag before checking the
manifest version and `main` ancestry. Guard and matrix builds have contents-read
only; the final publication job alone receives contents-write and OIDC. Release
notes are written to a runner-temporary file consumed through `body_path`, and
the generated Cosign command binds verification to the exact repository,
`release.yml`, and tag identity.

Docker publication is manual-only, accepts one required exact stable tag through
an environment variable, verifies that it names a published non-draft,
non-prerelease GitHub release, and runs only when dispatched from the default
branch. Dispatches are serialized, every accepted historical release can only
publish its immutable version alias, and `latest` moves only after a fresh API
check confirms the selected tag is still GitHub's current latest release.
Release guidance now records the explicit second authorization and the
non-cascading `GITHUB_TOKEN` boundary.

Repository-policy tests cover job permissions, annotation rejection, release
body transport, exact certificate identity, manual Docker dispatch, safe input
handling, latest-alias rollback prevention, and isolation from global Git
signing configuration. The Bun policy suite, adversarial signing-config
regression, `actionlint`, `bash -n`,
`shellcheck`, skill validation, issue-registry validation, and `git diff
--check` passed. No release, Docker image, tag, or remote configuration was
created or changed. Platform-enforced tag rules, branch protection, and release
environment approval remain open under IC-014.
