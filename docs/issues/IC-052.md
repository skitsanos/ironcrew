# IC-052 — Provider error context executes runtime interpolation during recovery

## Finding

`src/engine/task_runner/error_handler.rs` appends untrusted provider error text
to the fallback task's configured `context`. `TaskExecutionContext` then
interpolates that entire context, so provider-returned `${env.NAME}` can read
allowlisted runtime environment values and `${results.task.output}` can read
or remove result text. The allowlist authorizes trusted flow templates, not
provider diagnostics to select secrets.

This is separate from IC-034's HTTP/error response hygiene and IC-022's shell
environment inheritance. It also differs from TranscriptIntel TI-CREW-017's
flow-specific literal source/metadata encoding.

## Evidence and reproduction

On 2026-10-21, a fresh execution of the unchanged IronCrew 4.0.2 debug binary
against a disposable synthetic Lua flow and one owned loopback mock reproduces
the issue: a primary HTTP 503 message containing an authored allowlisted
environment expression causes the fallback provider request to contain its
fake value and lose the original expression. One case, seven assertions and
two mock requests pass. The primary prompt contains neither the fake value
nor the expression. The child environment is scrubbed, only an authored fake
value is allowlisted, and all owned resources are removed. No real secret,
private transcript, shared database or external provider is accessed.

The original runnable reproduction and sanitized receipt are retained under
the TranscriptIntel App's ignored
`.artifacts/ui-qa/summary-failure-2026-10-20/independent-engine-error-context*`.
The current implementation phase is authorized to edit IronCrew; the original
diagnostic phase correctly left this repository unchanged.

## Required outcome and acceptance

- Preserve the configured fallback task context as a trusted template.
  Pass provider error diagnostics separately and append them as literal data,
  after declared dependency evidence, without interpolation or hooks.
- Preserve the public task/context API, provider/model selection, direct
  single-handler invocation, cancellation and checked usage accounting.
- Enforce the aggregate character limit and UTF-8 boundaries; a large error
  must not displace already-admitted dependency evidence.
- Add regressions for literal environment/result expressions, quotes/control
  characters/Unicode, trusted templates, prompt bounds, primary/fallback
  success/failure and cancellation. Include actual mock-HTTP Lua execution.
- Run Rust format, Clippy with denied warnings, all-target tests, module-size
  and repository Python checks, Lua examples, security audit and issue-registry
  generation/check. Requalify the affected TranscriptIntel Crew contracts with
  the rebuilt local runtime; no deployment or live provider call is required.

## Outcome and validation

Recovery now borrows the unchanged handler definition and passes a short label
and the borrowed diagnostic separately to a crate-private executor method.
The public `TaskExecutionContext` fields and execution entry points are
unchanged. Only configured templates enter the interpolator; diagnostics never
enter interpolation or hooks. Normal prompt-section order is unchanged.

Prompt assembly is isolated in `executor/prompt.rs`. The diagnostic uses a
separate buffer sized to the remaining character allowance after normal
evidence. Its truncation marker cannot trim previously admitted dependency
text, including when less than one marker's space remains. Unicode truncation
remains safe, and the error message is not first copied into an unbounded
combined context. No prompt or request limits were increased. The executor's
reviewed module-size ceiling is ratcheted from 384 to 359 lines.

The original negative regressions failed before the fix for literal-error
handling and displaced dependency evidence. The updated tests verify those
boundaries plus selected model, trusted result interpolation, one checked
receipt on success/failure and partial cancellation settlement with zero
in-flight work. A tracked actual-CLI/Lua/HTTP regression uses a scrubbed child
environment and fake allowlisted values to cover handlers with no configured
context, trusted configured context and handler failure.
