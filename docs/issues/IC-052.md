# IC-052 — Provider error context executes runtime interpolation during recovery

## Finding

Untrusted provider diagnostics were appended to a fallback task's configured context before runtime
interpolation. Expressions in provider errors could therefore select allowlisted environment values
or task results. The trust granted to configured flow templates must not extend to diagnostics.

## Outcome and validation

The configured handler is preserved as a trusted template. Diagnostics enter the executor separately
and are appended as literal data after configured context and admitted dependency evidence. They do
not enter interpolation or hooks. Prompt limits, UTF-8 boundaries, cancellation, model selection and
checked usage remain enforced. The public execution context API is unchanged.

## Regression coverage

`tests/error_context_test.rs` covers literal environment/result expressions, trusted templates,
handler failure and cancellation, checked usage, Unicode and dependency-evidence preservation under
small prompt budgets. `tests/error_context_http_test.rs` executes the actual CLI/Lua path against
loopback mock HTTP providers with synthetic allowlisted values. No real credentials are fixtures.

The security implementation and these generic regressions are retained. Product-specific integration
narratives, filesystem paths and external acceptance receipts have been removed from this issue.
Repository validation for subsequent cleanup is recorded in its owning change, without claiming a
release or deployment.
