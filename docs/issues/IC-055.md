# IC-055 — Legacy run history has no read-only inspection path after checked-usage migration

## Finding and scope

The strict v4 runtime decoder deliberately rejects task results without checked `usage` (IC-046).
The separately authorized legacy-history reader must recover inspection access without changing
that execution contract. The 2026-10-24 TranscriptIntel native PostgreSQL restore contains 137 current
run records: 80 fail full runtime decoding because 124 task results have legacy `token_usage` but no
checked receipt. All other required task fields are present. Current CLI inspection bootstraps a
runtime store, which can initialize schema/reconcile state, so it is not a read-only recovery tool.

## Required outcome and acceptance

Add explicit PostgreSQL history list/inspect commands using read-only sessions and transactions,
without runtime startup, migrations, reconciliation, flow-directory assumptions or provider calls.
Return a separate non-executable history view; retain original raw fields and mark missing checked
usage unknown. Never reconstruct receipts from legacy counters or weaken `TaskResult`/`RunRecord`
decoding, replay, resume, HTTP authorization or normal store behavior. Malformed present checked
usage must still fail closed. Bound query work and returned data, and sanitize failures.

### Verification

Synthetic negative/current/legacy/mixed/large-count fixtures; least-privilege read-only PostgreSQL
coverage on the support floor and latest stable; actual CLI verification against an isolated native
restore of every original run, with complete before/after data/schema equality. Preserve all original
records, including empty scopes and unknown usage. Run required Rust/repository/Lua checks and clean
only owned temporary resources. No production access, commit, push, release or deployment is authorized.

## Outcome and validation

Resolved in a local uncommitted candidate based on develop
`64461e6fe75b8c1438e061c60146b4445639be3e`. Separate `history list/inspect` commands require explicit
process configuration and use bounded, sanitized, read-only PostgreSQL access. They never initialize
a runtime store, load `.env`/flows, mutate schema/history, execute providers or adapt executable
records. Missing checked usage remains null; existing unavailable snapshots remain unavailable.
Original raw JSON, including arbitrary-precision legacy numbers, is preserved verbatim. Present
malformed/null/contradictory checked receipts fail closed.

All **137/137** isolated original run rows are listed and inspected, including 80 previously blocked
legacy runs, 124 legacy task results and 64 empty flow scopes. All **124** missing checked task usages
stay unknown and all 137 checked run snapshots match their originals. The complete 19-table/8,371-row
database and schema have an identical normalized native dump fingerprint before/after. The actual
snapshot has zero populated checked task results; current/mixed receipts are covered by authored
fixtures. No production connection or historical rewrite occurs.

Independent review corrected two gaps within this boundary: ordinary JSON `Value` rounded legacy
numbers, and the initial integration fixture required CREATEROLE. Raw JSON preserves exact numbers;
the final fixture uses CI's restricted role, while the separate restore setup supplies SELECT-only
access. Ten focused regressions pass. Required formatting and Clippy with denied warnings pass;
`cargo test --all-targets` passes **1,570 tests with three intentional ignores**. The separate five-suite
PostgreSQL gate passes **78 tests on 17.11 and 78 on 18.6**, using restricted roles and only authored
integration databases. Doctests, dependency audit, Lua examples/offline probes, repository/module
policy, workflow lint, registry and final worktree/documentation checks pass.

Both owned containers/anonymous test volume, decrypted restore/configuration/private diagnostics and
4,329,954,855 bytes of owned build cache are removed. The original encrypted archives and separate
key are preserved; safe aggregate receipts and one qualified local executable are retained. Unrelated
existing IC-052 changes are preserved. See the [full acceptance receipt](../legacy-history-reader-acceptance.md)
for exact source/executable identities, data equality, versions/digests, coverage limits and cleanup.

Normal runtime/HTTP decoding, accounting, replay and resume stay strict and unchanged. This resolves
local operator inspection, not complete executable-history compatibility or an engine downgrade.
At the initial local acceptance, the candidate remained unpublished and undeployed; no commit,
push, service restart or provider call was performed in that phase. Hosted candidate qualification
is separately authorized below; production use remains separate work.

## Hosted candidate qualification follow-up — 2026-10-25

Source status remains resolved. Independent denied-warning review identified a feature-disabled
binary gap: the new pure decoder was also compiled into a private duplicate module tree without a
PostgreSQL caller. The reader and its CLI adapter now live only in the public library; the binary
delegates through that boundary. This preserves the pure decoder in no-default builds without new
lint suppressions. Both CI and pre-push explicitly run no-default binary Clippy with denied warnings and the pure
decoder integration tests; default all-target Clippy/tests remain mandatory. An exploratory
no-default all-target Clippy run exposed existing HITL test-only unused helpers; that broader
feature-disabled test configuration remains unqualified and is not claimed as passing.

The CI release-build job now binds its checkout to the exact selected source, retains a deterministic
Linux AMD64 archive with executable/archive hashes and source/repository/run/attempt receipt, and
uploads an immutable artifact ID. Separate PostgreSQL floor/latest jobs download that exact ID,
validate its receipt before extraction, and test the actual executable with SELECT-only authored
history. They cover exact large legacy numbers, unknown versus checked zero, unavailable snapshots,
malformed present usage, empty scopes, pagination, ancestor dotenv isolation and unchanged rows/schema.
Negative artifact tests reject wrong source/run bindings, tampering, path/link/extra members and
invalid binary metadata. File limits apply before bounded reads, extraction consumes the exact
hashed archive bytes, and source cleanliness is checked before/after build and packaging. No release
tag, release publication, registry promotion or deployment is added.

The actual local SQL/CLI probe also caught `psql` treating a URI in PGDATABASE as a database name
rather than selecting the intended loopback connection. The harness now splits the already validated
fixture URL into PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE in the private subprocess environment;
connection credentials never enter argv. The corrected actual local probe passes on PostgreSQL18.6:
four authored rows/schema unchanged, three valid records inspected, two unknown task usages and
checked zero preserved, malformed usage rejected, no provider calls. The reader role/table are
removed after the fixture. Supported no-default binary Clippy and all ten decoder tests also pass.

The repository's mandatory latest-stable refresh updates rusqlite to 0.41.0 and its compatible lockfile
graph before qualification. Exact local gates, hosted results and downloaded artifact identities are
recorded in the separately retained qualification receipt; they are not inferred from yesterday's
uncommitted 4.0.4 package version or earlier macOS executable.

The first hosted producer and both exact-ID consumers passed, but metadata exposed a documentation
mismatch: the workflow requests 14-day retention while artifact12592115113 reports expiry
2026-11-01T07:58:26Z (seven days from its run). Qualification guidance now treats the API-reported
expiry as authoritative instead of promising the requested duration. The corrected documentation
revision is qualified separately; no repository retention policy is changed.
