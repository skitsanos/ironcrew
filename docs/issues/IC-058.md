# IC-058 — Repository toolchain pins fail the required latest-stable gate after Rust 1.100.0

## Finding

Reproduced on 2026-11-20 by the pre-push gate: the latest-stable refresh
rejected every push because the repository pinned Rust 1.99.1 while stable
resolved to 1.100.0 (released 2026-11-09). The same refresh then required
cargo-audit 0.23.0 in CI, the current `docker/login-action` (v4.8.0) and
`sigstore/cosign-installer` (v4.1.3) releases, and the latest compatible
direct dependencies. The `=0.9.0` `sqlx` dev-dependency pin blocked the
lockfile once the runtime requirement moved to `sqlx` 0.9.1. This is the same
class of drift as [IC-054](IC-054.md).

## Outcome and validation

- `rust-toolchain.toml`, `rust-version`, the Dockerfile builder
  (`rust:1.100.0-bookworm` with its image digest), every
  `dtolnay/rust-toolchain` pin (branch `1.100.0`, by commit SHA) and the
  repository-policy expectations now agree on Rust 1.100.0. README and the
  deployment and API docs name the new builder version; historical release
  notes and issue pages are unchanged.
- CI installs cargo-audit 0.23.0; the release and Docker publish workflows
  use the two refreshed actions by commit SHA, and the trusted-action list
  matches.
- `cargo upgrade --incompatible` raised `jsonschema` to 0.61, `rusqlite` to
  0.43, `nix` to 0.32 and `rmcp` to 3.11 with compatible patch updates; the
  `sqlx` dev pin moved to `=0.9.1`. The chat UI lockfile was refreshed.
- Validation: the refresh script passes without changes, `cargo fmt --check`
  and `cargo clippy --all-targets -- -D warnings` pass without code changes,
  and the complete pre-push gate (tests, audit, PostgreSQL floor and latest,
  release build) ran before the push. Hosted CI is recorded on the pull
  request.
