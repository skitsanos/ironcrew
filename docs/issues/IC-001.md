# IC-001 — Owner death lacked a no-takeover replay acceptance gate

## Outcome and validation

**Resolved locally on 2026-07-20.** The existing two-process PostgreSQL 15
acceptance target now starts a keyed HITL run on replica A, proves it is durably
`WaitingForInput`, sends actual Unix `SIGKILL` to A, and keeps replica B alive
through the database-clock lease expiry. B's normal maintenance loop reconciles
the original row to `Abandoned`, clears the lease and encrypted mailbox, and
remains ready.

An immediate replay after the owner is reaped proves the retained response is
safe before reconciliation. Further retries span lease expiry and
reconciliation, followed by four concurrent post-terminal retries. Every
response is marked as a replay and retains the original run ID and owner;
HTTP run totals and exact PostgreSQL run/event row counts remain unchanged.

The isolated target passed 1/1 in 17.90 seconds and the complete PostgreSQL
integration slice passed 41/41. This proves no duplicate durable IronCrew
execution for the same principal/key/request during retention. It does not
prove arbitrary external provider/tool effects exactly once, execution
takeover, or Railway/OpenShift routing.
