# IC-038 — Documentation and example drift across nodes, endpoints, and model pins

## Finding

A documentation audit that verified every `IRONCREW_*` env var, ~30 defaults, all
CLI flags, every REST route, and all 28 SSE event names found the set accurate
apart from the following drift (plus IC-024, filed separately):

- `GET /nodes` registers 9 built-in tools and omits `ask_human`
  (`src/api/handlers.rs`), while `ironcrew nodes` registers 10 including it
  (`src/cli/commands.rs`). `docs/rest-api.md` ("all registered built-in tools")
  and `docs/cli.md` ("all 10") paper over a real CLI/API inconsistency.
- `docs/architecture.md` places `cmd_serve` in `src/api/mod.rs`; it lives in
  `src/cli/server.rs`.
- The `docs/cli.md` serve endpoint table omits `POST /flows/{flow}/abort/{run_id}`,
  `GET /flows/{flow}/questions/{run_id}`, `POST /flows/{flow}/answer/{run_id}`,
  and `GET /audit`, all registered in `src/api/mod.rs`. `docs/rest-api.md`
  documents them, so this misleads only readers who stop at `cli.md` — but the
  abort and HITL endpoints are load-bearing.
- `docs/cli.md` and `docs/storage.md` say `IRONCREW_STORE` accepts exactly
  `json`, `sqlite`, or `postgres`; `src/engine/store.rs` also accepts
  `postgresql`.
- `docs/cli.md` describes `IRONCREW_ENV_ALLOWLIST` as "exact env var names" while
  `docs/tools.md` correctly notes matching is case-insensitive
  (`src/utils/env.rs`).
- Example drift: `examples/anthropic/crew-thinking.lua` pins a superseded
  `claude-sonnet-4-20250514`; `examples/mcp/stdio-tools/.env.example` omits the
  provider key its flow requires; `examples/config-lua/config.lua` claims
  `crew.lua` can override individual router purposes, but the defaults merge in
  `src/lua/api.rs` is shallow, so a `models` table replaces the whole router.
- The MCP examples (`examples/mcp/stdio-tools/crew.lua`,
  `examples/mcp/http-tools/crew.lua`) pass `role`, `backstory`, and `max_iter`,
  which `agent_from_lua_table` never reads (see IC-028 for the silent-drop
  mechanism).

## Outcome and validation

**Resolved on 2026-08-19.** Every drift item in the finding is corrected.

The `/nodes` inconsistency was a real defect, not just a documentation gap: the
CLI and the HTTP handler each built their own registry and the HTTP one omitted
`ask_human`. Both now call a single `builtin_tool_catalog()`
(`src/tools/mod.rs`), so the two listings cannot diverge again, and a unit test
pins the exact ten-tool set with a message telling the next author to update the
CLI and HTTP docs together. `ironcrew nodes` reports ten tools.

Documentation: `docs/architecture.md` points `cmd_serve` at `src/cli/server.rs`;
the `docs/cli.md` endpoint table gains `abort`, `questions`, `answer`, and
`/audit`; `IRONCREW_STORE` is documented in both `docs/cli.md` and
`docs/storage.md` as accepting the `postgresql` alias case-insensitively; and the
`IRONCREW_ENV_ALLOWLIST` wording in `docs/cli.md` now matches
`docs/tools.md` and `src/utils/env.rs` on case-insensitive full-name matching.

Examples: `examples/anthropic/crew-thinking.lua` moves to
`claude-sonnet-4-5-20250929`; `examples/mcp/stdio-tools/.env.example` gains the
provider key with the same explanatory header the sibling examples use; the
`examples/config-lua/config.lua` comment now states that the defaults merge is
shallow, so a `models` table in `crew.lua` replaces the router wholesale. The
unsupported `role`/`backstory`/`max_iter` agent fields were removed from both MCP
examples as part of [IC-028](./IC-028.md).

Validation: `cargo test --all-targets` (55 binaries, 0 failures) including the
new catalog test; `scripts/check-lua-examples.sh` (65 files validated, 5 offline
probes passed); `ironcrew nodes` output inspected directly.

Boundary: the OpenAI model split across examples (`gpt-5.6-luna` vs
`gpt-5.4-mini`) was left as-is — it appears to be deliberate cost-tiering rather
than drift, and changing it would alter what the examples cost to run.
