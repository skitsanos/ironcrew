# IC-042 — Dialog turns accept blank model replies and burn the turn budget

## Finding

`src/lua/dialog.rs` rejects a missing final reply (`content: None`) with
`Empty response from LLM`, but accepted `Some("")` and whitespace-only content
as completed turns. A blank turn was appended to the transcript, counted
toward `max_turns`, replayed into the next speaker's history, and handed to
`should_stop`, which cannot match a content marker against an empty string.

Observed live on 2026-09-20 with `examples/dialog-early-stop` on the plain
`openai` provider: after one negotiator replied with the bare marker `AGREED`,
the model returned consecutive empty completions and the dialog continued to
the 20-turn safety cap. The same example can also complete normally, so this
is a dialog-loop robustness gap rather than a deterministic example defect.

## Required outcome and acceptance

A blank final model reply must not count as a dialog turn. Prefer a distinct
early-stop reason so `dialog:stop_reason()` and the dialog SSE event explain
the outcome. Cover both automatic and forced-speaker dialog drivers, empty and
whitespace-only replies, event cardinality, and prevention of subsequent
provider calls.

## Outcome and validation

**Resolved on 2026-09-20.** `execute_turn` now treats an empty or
whitespace-only final reply as an early stop after zero or more tool rounds.
Nothing is appended to the transcript, the dialog records
`stop_reason = "empty_response"`, and `dialog_completed` is emitted exactly
once with `total_turns = 0`. Both automatic and forced-speaker turn drivers
return `nil`, so later calls do not invoke the provider. A missing final reply
(`content: None`) retains its existing provider error.

Regression coverage in `tests/dialog_empty_reply_test.rs` exercises both
drivers and the tool-assisted final-reply boundary through the Lua API. It
asserts zero recorded turns, one `dialog_completed` event, no `dialog_turn`
event, and no provider call after the blank reply. The extracted
`src/lua/dialog_stop_tests.rs` preserves the existing `should_stop` and
dialog-history unit coverage while ratcheting the legacy module ceiling.

Validation: formatting, warning-denied Clippy, all-target tests, doc tests,
module-size and repository-policy suites, the issue registry, and Lua example
validation.

Boundary: tool calls may already have produced side effects before their
blank final reply stops the dialog. `content: None` remains a provider error.
