# IC-048 — Current builds lack recurring bounded live-provider compatibility smoke

## Finding

CI exercises syntax, offline Lua probes, and the mock-provider effectiveness
contract. A live evaluator already exists, with a retained 180-run Luna receipt
from 2026-08-12, but that receipt binds IronCrew 2.24.0 and its frozen corpus.
It does not establish current-build compatibility or recurring coverage of
model-option changes, tool behavior, blank replies, and dialog termination.

Evidence: `.github/workflows/ci.yml`, `scripts/check-lua-examples.sh`, and
`evaluations/crew-effectiveness/README.md`. This extends acceptance freshness,
not the comparative effectiveness finding resolved in [IC-009](./IC-009.md).

## Outcome and validation

Implementation started on 2026-09-21 after the validated IC-046/IC-047
checkpoint `48729e5`. The initial selected model is `gpt-5.6-luna` through native
Responses, with `low` effort (and one explicit `none` canary). Four sequential
CLI/HTTP cases share a reviewed 40,000-token total envelope; nightly activation
remains disabled pending the owner's operational approval.

Implemented `evaluations/live-smoke/` with provider-free plan and contract modes,
explicit live opt-in, secret-minimal environment reuse, checked accounting,
fail-fast bounded subprocess/PTY/HTTP execution, scripted two-agent human input,
and sanitized source/binary-bound receipts. The fixed envelope has four serial
runs, 10,000 tokens per run, 1,024 output tokens per request, at most 47 generation
and 47 input-count requests, a 300-second work deadline, and a conservative
$0.12 upper estimate under a non-expandable $0.15 ceiling. Pricing review expires
after 30 days; provider/credential configuration and stale pricing fail closed.

Regular CI and the local pre-push gate run the offline tests, never paid calls.
The separate workflow offers owner-only manual dispatch and 03:17 UTC nightly
execution from the default branch, protected environment access, approval flags,
read-only repository permissions, serialized jobs and seven-day receipt retention.
No remote variable, secret, environment, schedule or approval setting was changed.

### Defect found by the live probe

The first tool-enabled native input-count request failed with HTTP 400
`invalid_function_parameters`: `ask_human`'s optional-property schema was
incorrectly advertised as strict. IC-047 correctly denied generation. The shared
Responses builder now explicitly sends `strict: false` for function schemas,
preserving optional fields without rewriting their meaning. Strict structured
response formats, tool execution validation and human approvals are unchanged.
The regression failed before the fix and passed afterward. Native-count fixture
tests verify identical tool schemas in admission and generation; the offline
smoke provider rejects the incorrect strict claim too.

### Original acceptance criteria

- Add a small opt-in live smoke harness reusing appropriate existing evaluation
  infrastructure. Keep its compatibility claims separate from effectiveness
  scores and historical immutable receipts.
- Cover selected current provider/API/model configurations, valid reasoning
  options, tool invocation, blank/final-output handling, and bounded dialog stops.
  Include representative CLI and serve/HTTP paths, with scripted HITL
  approval/denial coverage rather than an unattended human wait.
- Assert nonblank successful output, bounded requests/turns/tokens, complete
  terminal states, and usage coverage rather than exact generated wording.
  Record source/binary/model identity, timestamp, transport, parameters,
  failures, latency, usage, and conservative cost estimates.
- Support provider-free plan inspection and enforce approved request, time,
  token, concurrency, and spending-estimate limits. Read credentials only from
  the approved environment and never disclose them in logs or reports; skip
  distinctly when disabled or unconfigured.
- Provide manual invocation and a gated nightly CI option with safe credential
  boundaries, bounded report retention, and no execution of untrusted fork code
  with secrets. Distinguish provider outages from contract regressions.
- Preserve deterministic offline regressions for known failures; live smoke
  supplements them rather than becoming the only regression coverage.
