# IC-030 — Foreach total failure does not gate dependent tasks

## Finding

In `src/engine/orchestrator.rs`, `failed_tasks.insert(...)` runs only in the
"skipped" branch (empty agent, i.e. a non-array foreach source). A foreach task
whose items all errored returns `success: false` with a non-empty agent
(`src/engine/foreach.rs`), so it takes the other branch, emits
`TaskCompleted { success: false }`, and is never added to `failed_tasks`.

For a standard task, failure causes dependents to be skipped with a `TaskSkipped`
event via `filter_eligible_tasks`. Here the dependents run anyway, and because
the executor only injects successful dependency outputs into a task's context
(`src/engine/executor.rs`), they execute with their input context missing —
spending provider tokens on effectively empty input and emitting a misleading
`TaskCompleted` for the failed foreach.

## Outcome and validation

**Resolved on 2026-08-19.** A foreach task whose every item fails now gates its
dependents exactly like a failed standard task.
`execute_foreach_task` returns a `ForeachOutcome` (`src/engine/foreach.rs`)
carrying the task result plus executed- and failed-item counts, and
`src/engine/orchestrator.rs` treats a wholly failed foreach as a failure: it
emits `TaskFailed` and inserts the task into `failed_tasks`, so dependents are
skipped with `TaskSkipped` instead of running with no usable input.

Partial failure is deliberately unchanged: when at least one item produced
output, the foreach still reports completion and dependents run, because the
output array carries usable content.

Regression coverage: `tests/foreach_failure_gating_test.rs` drives a real crew
with a provider that fails every item and asserts the dependent task is never
dispatched, is recorded as skipped, and that the foreach genuinely ran its items
(per-item `Error:` entries present, no skip-path marker). A second test with one
succeeding item asserts the dependent still runs, proving the fix does not
over-gate.

Validation: `cargo test --all-targets` (55 binaries, 0 failures), clippy clean.

Boundary: the two pre-existing skip paths (non-array source, empty source) keep
their current semantics.
