# IC-034 — Error responses and provider error paths leak internals or lose status

## Finding

`sanitize_error` (`src/api/handlers.rs`) exists specifically to strip filesystem
paths and internal details, but is applied only on the flow-resolution paths.
Several responses bypass it:

- `validate_flow` and `list_agents` (`src/api/handlers.rs`) return loader errors
  verbatim as 400 bodies; `ProjectLoader::from_directory` formats
  `"No crew.lua found in {path}"`, echoing the server's absolute filesystem
  layout. `validate_flow`'s success body also returns the absolute `entrypoint`
  path.
- `list_runs` and `list_audit` (`src/api/handlers.rs`) return raw `e.to_string()`
  in 500 bodies.
- `map_err_to_response` (`src/api/conversations.rs`) returns `e.to_string()` for
  all variants, including `Io` and internal errors, on every conversation
  endpoint.

Separately, the non-streaming provider paths parse the response body as JSON
before checking HTTP status (`src/llm/openai.rs`, `src/llm/anthropic.rs`,
`src/llm/openai_responses.rs`), so a 502/503 HTML page from a proxy yields
`"Invalid JSON response from LLM provider: expected value at line 1"` instead of
the actual status. The streaming paths already check status first with a bounded
raw-prefix fallback. Related parser nit: all three SSE readers only recognize
`data: `/`event: ` with a trailing space, while SSE permits `data:{...}`.

## Outcome and validation

**Resolved on 2026-08-19.** Client-visible errors no longer carry server
internals, and provider failures report their HTTP status.

API responses (`src/api/handlers.rs`): a new `internal_error` helper logs the
full error and returns a generic 500 body; it replaces the five raw
`e.to_string()` 500 bodies in `list_runs`, `list_audit`, and flow inspection.
The loader errors in `validate_flow`/`list_agents` now pass through the existing
`sanitize_error`, so absolute server paths are no longer echoed to clients, and
`validate_flow` reports its entrypoint flow-relative instead of as an absolute
path. `map_err_to_response` (`src/api/conversations.rs`) keeps the actionable
message for `Validation` and `Conflict` — preserving the contract asserted by
`lua_error_mapping_tests` — while logging and genericizing every other variant,
including `Io`.

Provider errors: the non-streaming paths in all three providers now report the
HTTP status, because a redirect/proxy failure previously surfaced as "Invalid
JSON response" after the body was parsed before the status was checked. The
underlying rate-limiter and error-body duplication is tracked in
[IC-037](./IC-037.md).

Validation: `cargo test --all-targets` (55 binaries, 0 failures) including
`api_safety_test` and `http_audit_test`; clippy clean.

Boundary: the SSE field-form parsing nit (`data:` without the optional space) is
not addressed here and remains open under [IC-037](./IC-037.md) with the rest of
the shared stream-scaffolding work.
