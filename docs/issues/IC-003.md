# IC-003 — Local run fence can outlive the PostgreSQL lease deadline

## Outcome and validation

**Resolved locally on 2026-08-07.** Run and conversation heartbeat deadlines
now begin at the storage invocation, and a successful response renews the
process-local fence to `invocation + TTL`, never `response arrival + TTL`.
PostgreSQL continues deriving the durable deadline from its own clock; JSON
and SQLite persist the proposed absolute deadline but finish their owned
blocking work before accepting a late result. The backend contract documents
that ordering explicitly.

A keyed HTTP run establishes a durable ledger heartbeat before Lua is spawned.
The PostgreSQL claim-to-running transition additionally requires the matching
claim to be live and cancellation-free on the database clock. A shared
mutex-protected coordinator serializes current-deadline renewal, terminal/lost
publication, and a one-shot worker-start gate. The monitor uses a biased,
fence-first select, so an already-expired or lost fence leaves the Lua body
unpolled; heartbeat task cancellation or panic publishes `Lost` fail-closed.
Late completion remains owner/status compare-and-set protected.

Focused deadline/coordinator unit tests passed 10/10, and worker-gate tests
passed 2/2: an expired keyed fence observed zero worker-body polls while an
unkeyed worker retained its immediate behavior. Live PostgreSQL coverage
injects 500 ms after database deadline sampling and observes the reduced
remaining lease, rejects a claim expired before run-intent publication, and
preserves ledger/run deadline equality. The real two-process target then
misses two minimum-TTL heartbeats under confirmed `SIGSTOP`, renews after
`SIGCONT`, and later proves peer reconciliation plus stale-terminal CAS after
owner death. Exact all-target Clippy and the process gate passed.

This closes IronCrew's local admission/fencing mismatch. It does not claim
exactly-once behavior for provider or tool effects already issued before a pod
stalls or dies; those operations still require their own idempotency keys.
