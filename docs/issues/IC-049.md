# IC-049 — Replica SSE acceptance races the terminal journal append

## Finding

The PostgreSQL acceptance test
`keyed_run_can_be_replayed_observed_and_cancelled_from_a_peer_replica` waits for
durable `Aborted` status and immediately requires a numbered SSE completion.
The terminal run row is deliberately committed before the terminal journal
append. Until the append is durable, the public contract allows an unnumbered
completion marked `journal_complete: false` and `synthesized_from_run_record: true`.
Terminal status is not a journal-flush barrier.

This race failed the PostgreSQL 17 leg of
[CI run 35606395872](https://github.com/skitsanos/ironcrew/actions/runs/35606395872)
on `3669359c9cb3fba53cacde9a182884537879ecff`, after that exact source had passed
main CI and full local gates. The failure was at the numbered-ID assertion;
the terminal event and aborted status assertions passed.

Sources: `tests/multi_replica_http_test.rs`, the persistence/append order and
synthetic fallback in `src/api/handlers.rs`, and the explicit non-barrier
contract in `docs/rest-api.md` and `docs/multi-replica.md`.

## Required outcome and acceptance

- Synchronize the numbered-replay test on a durable terminal event sequence,
  not only terminal run status. Keep the ID, status, flow/cursor and replay
  assertions intact; do not relax the production SSE contract.
- Bound the complete wait, including a stalled store read. Test delayed
  terminal appends and timeout behavior without a database.
- Repeat the affected live PostgreSQL test on both 17 and latest stable, then
  run the full Rust/repository/PostgreSQL/replica gates and exact-head CI.
- Preserve the already-pushed immutable `v4.0.0` tag. Its publication was
  cancelled before protected approval; no GitHub release or Docker promotion
  occurred. Publish the corrected source as `v4.0.1` through the normal gates.

wait, including an individual stalled store read, has a 12-second deadline.
