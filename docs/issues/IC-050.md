# IC-050 — Renovate rewrites receipt-bound canary assembly Dockerfiles

## Finding

The platform-canary assembly Dockerfiles are retained evidence. Each one
records the exact bytes that assembled a historical canary image, and the
receipts pin those bytes by SHA-256:

| Tracked file | Receipt binding | Recorded SHA-256 |
|---|---|---|
| `evaluations/platform-canary/reports/ic007-v6-assembly.Dockerfile` | `ic007-v6-assembly-context.json` | `6de0d031…f9723` |
| `evaluations/platform-canary/reports/ic007-v7-assembly.Dockerfile` | `ic007-v7-assembly-context.json`, `ic007-openshift-v7.json` `retained_assets` | `6de0d031…f9723` |
| `evaluations/platform-canary/ic008-openshift-assembly.Dockerfile` | `ic008-openshift-assembly-context.json` | `4a728b53…dbc1` |

`ic007-openshift-v5-assembly.Dockerfile` is named as the assembly Dockerfile
of both v5 precursor receipts, which did not pin its hash. The v7 report states
that "the exact assembly Dockerfile bytes … are retained as the canonical
`ic007-v7-*` assets".

Renovate treated all four files as live build inputs and rewrote their
`debian:13-slim` digest twice: `5aa3639` (2026-08-25) and `eb1be86`
(2026-09-19). After those commits, no tracked assembly Dockerfile matched its
receipt. Grouped refresh [#121](https://github.com/skitsanos/ironcrew/pull/121)
proposed a third rewrite. No repository check compared the files with their
receipts. A refresh could therefore relabel historical evidence while CI stayed
green.

## Required outcome and acceptance

- Restore every assembly Dockerfile to the bytes its receipts recorded, from
  the evidence commit `a3fea1c`. Do not regenerate or re-sign any receipt.
- Stop Renovate from proposing updates to retained assembly Dockerfiles. Keep
  the inherited `:ignoreModulesAndTests` scope unchanged, and keep the release
  `Dockerfile` and `docker/runtime.Dockerfile` managed. Repository policy
  forbids disabled package rules, so use `ignorePaths`.
- Add a regression that fails when a tracked assembly Dockerfile drifts from
  its receipt hash or size, or when the Renovate scope stops excluding exactly
  those files.
- Document that a new canary run must add new assembly files and receipts
  rather than editing retained ones.

## Outcome and validation

Resolved on 2026-10-07. The four assembly Dockerfiles were restored
byte-for-byte from `a3fea1c`. Each restore reverses one `FROM` line. No
receipt was regenerated or edited.

- Restored SHA-256 values match every receipt binding:
  `4a728b53d06c7e262399035ab159d48adc5a5e7a6fc410ce22d92c06676bdbc1`
  (ic008, 992 bytes) and
  `6de0d031b6d5bc6078996bc13b8ca89ab22486c6b73065a047937b7c8e6f9723`
  (ic007 v5/v6/v7, 997 bytes).
- `renovate.json` sets `ignorePaths` to the inherited `:ignoreModulesAndTests`
  list plus `evaluations/platform-canary/**/*-assembly.Dockerfile`. Renovate
  44.142.0 `renovate-config-validator --strict` accepted the repository config.
  Renovate's own `filterIgnoredFiles`, run over all 976 tracked files, newly
  ignored exactly the four assembly Dockerfiles and newly managed nothing.
  `Dockerfile` and `docker/runtime.Dockerfile` remain managed.
- `scripts/tests/canary_evidence.test.ts` checks every receipt binding's size
  and hash, and the exact Renovate exclusion set. Negative probes: restoring
  the drifted v7 bytes failed on `a6c4d369…` versus `6de0d031…`, and removing
  `ignorePaths` failed with a readable diff. Both tests pass on the restored
  tree.
- Bun policy tests (61 tests, 577 assertions), repository Python tests (76),
  platform-canary contract tests (42), module-size policy (41/41 legacy
  exceptions), and the issue registry check passed. This change touches no
  Rust, workflow, or Lua source.

Boundaries: the v5 precursor receipts name their assembly Dockerfile without
pinning a hash. It was restored to the same evidence-commit bytes but is only
checked through the Renovate scope. The `build_inputs` hashes for the root
`Dockerfile` record the release Dockerfile at build time and are expected to
differ from the current file. The Renovate exclusion is proven only against
Renovate's own matcher, locally.

Hosted Renovate reads repository configuration from the default branch, `main`.
On `main`, `useBaseBranchConfig` is unset, so the exclusion takes effect only
when this change reaches `main`. `develop` now sets `useBaseBranchConfig:
"merge"`, but that setting is also read from `main`, so it activates with the
same release. Before then, a hosted Renovate 44.134.1 run
opened [#122](https://github.com/skitsanos/ironcrew/pull/122) against `develop`
at `e5796d4`. It proposed the `a29215f` `debian:13-slim` digest for all four
files. `canary_evidence.test.ts` failed that PR's Repository policy job as
designed, and the PR was closed unmerged. The first hosted run after release to
`main` is the platform evidence.
