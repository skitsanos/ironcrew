# IC-036 — Residual HTTP hardening gaps in proxy trust, timeouts, CORS, and audit coverage

## Finding

Four independent gaps remain in the HTTP surface:

- `extract_source_ip` (`src/api/audit.rs`) takes the leftmost `X-Forwarded-For`
  entry when `IRONCREW_TRUST_PROXY` is set. Standard proxies append the peer
  address, so the leftmost value is client-supplied: a request with a forged
  `X-Forwarded-For` writes an arbitrary source IP into every audit record,
  enabling audit-attribution forgery on the supported proxied deployments.
- `axum::serve` (`src/cli/server.rs`, `src/cli/server_shutdown.rs`) is configured
  with a body limit and CORS but no header-read timeout, no per-request timeout
  layer, and no connection cap. Byte limits are enforced; time limits are not, so
  a slow-loris client can hold a file descriptor and task per connection
  indefinitely before any semaphore applies. PaaS proxies mitigate this, but the
  binary also supports direct public binds.
- `IRONCREW_CORS_ORIGINS="*"` maps to `CorsLayer::permissive()`
  (`src/cli/server.rs`), allowing any method and any request header — broader
  than the explicit-origin branch, which restricts both to the API's actual
  surface.
- `post_message` (`src/api/conversations.rs`) records an audit event for
  idempotent outcomes and non-idempotent successes, but every non-idempotent
  failure and pre-claim rejection returns without an audit record. `abort_run`,
  `delete_run`, `answer_question`, and `start_conversation` all audit both
  outcomes; `post_message` is the outlier, and failed mutation attempts are
  exactly what an operator wants recorded.

## Required outcome and acceptance

Audit source IPs must not be attacker-settable: select the rightmost untrusted
hop or use a configured trusted-proxy count/CIDR. Add request/header read
timeouts (and consider a connection cap) for non-SSE routes. Build the wildcard
CORS case from the same restricted method/header sets as the explicit-origin
branch. Apply the existing result-wrapping audit pattern to `post_message` so
failures are recorded. Add coverage for forged-XFF rejection and for an audited
`post_message` failure.

### Status note — 2026-08-19

Not yet implemented. Note that the four gaps are independent and can land
separately; the `X-Forwarded-For` trust fix is the highest value of them,
because forged audit attribution is silent and the supported PaaS deployments
are exactly the proxied topology where it applies.
