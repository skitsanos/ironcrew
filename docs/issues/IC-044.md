# IC-044 — Provider and model capability rules lack one shared policy

## Finding

`src/lua/config_choices.rs` validates a union of reasoning-effort names rather
than model-specific support. Chat Completions Luna/tool restrictions live in
`src/llm/openai/reasoning_effort.rs` and `request_body.rs`; token-field and
temperature behavior are handled separately across provider implementations.
Construction validation and request building can therefore disagree, leaving
unsupported combinations to fail only on a paid provider request.

## Outcome and validation

**Resolved locally on 2026-09-20.** `src/llm/capabilities.rs` and its small
catalog now own effort, temperature, token-field, and tool/reasoning rules.
Provider request builders use the same offline validation hook as Lua crew,
agent, conversation, and dialog construction; the metrics wrapper forwards it.
Per-agent overrides are checked against the effective model, and final
request construction rechecks task/session overrides and actual tools.

The default remains `gpt-5.6-luna`. Omitted effort is `low`, or `none` for
Luna Chat Completions function tools. `minimal` is a negative test case, never
the Luna default. Explicit incompatible settings fail instead of being rewritten.
Custom endpoints do not inherit official OpenAI model rules by model spelling.
Official Chat Completions uses `max_completion_tokens` independently of model
names; custom Chat Completions retains its documented `max_tokens` contract.
Provider fingerprints include the policy revision so changed defaults cannot
silently resume an existing persistent conversation.

Anthropic's manual-thinking adapter now checks temperature, budget/output
bounds, forced JSON-schema tools, and known adaptive-only model restrictions.
It still does not implement native adaptive thinking or `output_config.effort`.
Two old isolated guard modules were replaced by the shared policy. Request
builders and related construction/tests were extracted into focused modules;
all new production modules are below 300 lines, and the reviewed legacy
exception budget was ratcheted from 47 to 46.

The original accepted contract was:

- Introduce a small typed, data-driven capability policy keyed by provider/API
  transport and model identity, with explicitly bounded family/version matching.
- Represent supported effort values, temperature policy, output-token field
  selection, and tool/reasoning compatibility for the supported configurations.
- Use the same policy in construction validation and request building. Reject
  explicit unsupported choices clearly rather than silently rewriting them.
- Define and document unknown/custom-model behavior without assuming an
  OpenAI-compatible endpoint has official OpenAI model semantics. Preserve the
  ability to configure legitimate custom providers through an explicit contract.
- Verify current capability entries against official provider documentation at
  implementation time, recording sources and verification dates. Add fixtures
  for each supported transport and negative tests for invalid combinations.
- Demonstrate that the same input receives consistent acceptance/rejection in
  both construction and request paths, including per-agent overrides.

## Dependencies and boundaries

Package 2 foundation for [IC-045](./IC-045.md). A capability table is not proof
that a model remains available or behaves correctly; freshness checks and live
smoke belong to [IC-048](./IC-048.md). No automatic model replacement or
backward-compatibility layer is in scope.

## Validation evidence

- Two regressions first failed because unsupported Luna options reached
  credential preparation; both now fail locally with capability errors.
- Five offline integration tests cover Lua construction, agent model overrides,
  official/custom endpoints, invalid effort, and invalid temperature. Policy
  and wire fixtures cover all three transports, defaults, explicit overrides,
  bounded snapshot matching, and Anthropic thinking constraints.
- Passed `cargo fmt --all -- --check`,
  `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets`,
  `cargo test --doc`, `cargo check --locked --no-default-features`, and
  `cargo audit --deny warnings`.
- Passed module-size policy (305 production modules, 46/46 exceptions),
  76 Python repository tests, 28 Bun policy tests, three skill validations,
  actionlint, issue registry, and worktree whitespace checks.
- `./scripts/check-lua-examples.sh`: 67 files and five offline runtime probes.
  Evaluator: 74 unit tests and the deterministic contract's 36 CLI runs,
  96 mock requests, and 72/72 grounded answers passed.
- [Capability documentation](../model-capabilities.md), agent/crew/provider
  guidance, and provider examples now describe the defaults and explicit
  unknown/custom-model contract. Official sources were reviewed on 2026-09-20;
  the retained Luna temperature/tool restrictions are separately identified
  as prior repository evidence, not newly live-verified claims.

Evidence is local and offline/mock-backed. No paid provider call, live PostgreSQL
test, deployment, or platform-only CI run occurred. Existing credentials were
not changed or exposed. No commit or push was made for this work package.
`ironcrew validate` remains compile-only until IC-045.
