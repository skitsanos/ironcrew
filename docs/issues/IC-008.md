# IC-008 — Live conversation control remains process-owned

## Outcome and validation

The original finding was that PostgreSQL shared persisted transcripts while the
live Lua conversation handle, active turn, abort state, and conversation SSE
channel all remained usable only through one process. The committed
implementation narrows that boundary: a required-key PostgreSQL message can
reconstruct a compatible handle from a committed incarnation/revision on either
replica.
The active Lua/provider/tool turn still belongs to one process, and PostgreSQL
conversation SSE is deliberately unsupported, so this is not in-flight
execution takeover or a general high-availability claim.

The accepted outcome is:

- define fenced ownership for one active turn and deterministic behavior when
  flow source/model configuration changed since the persisted transcript;
- either broker commands to the owner or rehydrate a conversation safely from
  durable state after owner loss;
- make duplicate message admission and deletion races deterministic;
- provide bounded durable conversation SSE replay or a truthful unsupported
  boundary;
- preserve transcript byte/history limits and provider/tool cancellation; and
- pass start, message, history, delete, reconnect, owner-death, and
  rolling-restart cases through either of two real replicas.

Execution checkpointing for arbitrary runs is outside this issue unless the
conversation design explicitly requires and specifies it.

## Implemented boundary

The 2026-08-08 resume-safety slice first made a supplied agent mismatch return
`409 Conflict` before Lua construction. On 2026-08-11, the committed
implementation expanded that boundary into a versioned durable conversation
execution identity:

- a canonical non-nil UUID incarnation fences delete/recreate ABA reuse;
- one bounded no-follow capture supplies the exact immutable Lua bytes used for
  `config.lua`, `crew.lua`, direct `agents/*.lua`, `tools/*.lua`, `_lib`
  `require`, and nested `run_flow` during an HTTP conversation build. A second
  capture only detects rollout drift after construction; ordinary CLI/run
  execution remains filesystem-backed;
- source and definition fingerprints bind that sorted Lua snapshot, selected
  Agent, resolved model and system prompt, transcript limits, maximum tool
  rounds, effective non-secret provider endpoint/options, and the resolved tool
  graph. The constructed provider/tool runtime captures the effective
  non-secret provider rate/response/output policy, Lua/JSON/HTTP/conversation
  input limits, reasoning and dispatch limits, approval/network policy,
  sub-flow depth, and reachable capability-root fingerprints; turns use that
  captured policy rather than re-reading mutable environment settings;
- provider credentials are excluded, provider endpoints reject userinfo,
  query strings, and fragments, and persistent MCP tools require an explicit
  non-secret `execution_identity`;
- legacy identity-less transcripts remain readable through history/export and
  removable through delete, but start/resume/message fail closed with guidance
  to recreate them. SQL reads bound metadata, identity, transcript bytes, and
  message count before returning values to Rust; malformed, non-array, or
  oversized rows fail closed rather than being adopted as legacy data; and
- start and history expose revision, incarnation, source, and definition
  identity; message responses expose revision, incarnation, and definition
  identity for acceptance correlation.

PostgreSQL conversation messages now require `Idempotency-Key` regardless of
the global optional-key setting. The store claims the exact
`(flow, id, incarnation, base revision)` before a cold Lua handle is built, and
atomically commits the transcript revision with the retained response. A
message can therefore rehydrate a committed conversation on either replica,
including after the prior owner died between turns. The claim heartbeat,
indeterminate recovery barrier, cancellation, history byte/message limits, and
provider/tool timeout path remain in force. Active delete is rejected; a later
delete/recreate receives a new incarnation and cannot replay the old response.
Both the turn-owning replica and a peer return the active-delete `409`
promptly rather than waiting for or cancelling the turn.

That owner-death property is explicitly between turns. Death after
provider/tool work or commit may have started does not move the Lua VM to a
peer, and it does not prove that external effects were absent. The active key
remains indeterminate until the client inspects durable history and uses the
documented recovery-key barrier.

HTTP conversation discovery is host-enforced declarative-only: run,
conversation/dialog, HITL, sub-flow, HTTP, filesystem-write, crew-message, and
crew-memory effects are rejected before work starts during bootstrap. This
prevents cold rehydration itself from repeating top-level effects. Persistent
direct Lua/CLI turns on a shared store fail closed because they do not own the
HTTP durable turn claim. Secret values remain outside execution identity;
compiled-in limits and semantics travel with the independently attested
artifact identity rather than being serialized into conversation records.

Conversation SSE now has a truthful bounded boundary rather than a routing
illusion. PostgreSQL returns the same `409` unsupported response from either
replica and directs clients to durable history. JSON/SQLite streams remain
process-local, reject `Last-Event-ID`, and emit `conversation_gap` before
closing when a subscriber falls behind.
