# IC-054 — Repository toolchain pins fail the required latest-stable gate

## Finding and evidence

A candidate based on current `origin/main` (`25dc40f`) fails `task develop-refresh` before
compilation: the Rust manifest, toolchain, builder, workflows and policy tests select 1.99.0, while
`rustup update stable` resolves 1.99.1 (2026-10-15). The repository requires the latest stable pins
before publication. The gate correctly refuses the mismatch; it must not be bypassed.

This is separate from IC-051's grouped Wolfi image receipt and IC-053's TLS advisories.

## Required outcome and acceptance

Update all active toolchain references, immutable toolchain action commits, the qualified official
Rust builder digest and policy expectations consistently. Preserve historical release receipts.
Complete the prescribed latest-stable refresh, review its managed dependency/policy changes, and
run the clean complete pre-push gate with owned PostgreSQL floor/latest fixtures. Qualify the exact
published candidate in hosted CI; do not restart or deploy the retained local service for this phase.

## Progress

The candidate is isolated from the primary checkout and retained running binary. Rust 1.99.1 and
its action branch were resolved from rustup/the official toolchain repository. Final gate and hosted
receipts will be recorded after qualification. No live provider or shared database is used.

The required refresh also found Swatinem/rust-cache v2.9.3; immutable workflow pins and policy expectations are aligned. The managed refresh updated current Tokio, serde_json, jsonschema and rmcp requirements/lock entries and chat UI dependencies. TLS remains on the IC-053 patched versions. Historical release receipts were preserved. `task develop-refresh` and all 23 repository integration-policy tests now pass; complete gates are pending.

The complete manual gate passed on `4199ea5684578a0b13be8a2b7608ad55408067c5`,
including PostgreSQL 17.11/18.6, the provider-free replica soak and locked release build.
The normal push hook then correctly refused publication when a fresh registry resolution

The earlier success is retained as historical evidence, not qualification of these new bytes.
