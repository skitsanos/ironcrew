# IC-060 — Pre-push gate does not deny Rust warnings as CI does

## Finding

Reproduced on 2026-11-22 against `develop` at `622d1d0`.
`.github/workflows/ci.yml` sets `RUSTFLAGS: -Dwarnings` at workflow level, so
every CI cargo invocation denies compiler warnings: the
`cargo build --no-default-features` step in `Format, Clippy, and tests`, the
all-target tests, the PostgreSQL suites run by `scripts/check-postgres.ts`, the
Lua-example and evaluation debug builds, and the locked release build.
`scripts/pre-push-check.sh` runs the same commands without setting `RUSTFLAGS`.
Only `cargo clippy --all-targets -- -D warnings` denied warnings locally, and
Clippy runs with default features.

A helper used only by the PostgreSQL store therefore became dead code in the
no-default-features build. That warning passed the complete local gate and then
failed CI with `-Dwarnings`. The comparison found no other drift in the shared
Rust steps: the commands, feature sets, `--locked` usage and doc tests match.
CI's macOS test and Windows `cargo check` jobs remain platform-only CI
evidence. The gate's `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_DEV_DEBUG=0` are
deliberate local disk bounds. They do not change which lints run.

## Outcome and validation

- After the latest-stable refresh, before its first check, the gate clears
  `CARGO_ENCODED_RUSTFLAGS` (which Cargo prefers over `RUSTFLAGS`) and the
  rustdoc flag variables that CI does not set. It then exports
  `RUSTFLAGS=-Dwarnings` for every later step, including the PostgreSQL suites
  that inherit the gate environment. The refresh, temporary-directory admission
  and database URL handling are unchanged.
- `scripts/tests/pre_push_rustflags.test.ts` parses the workflow and the gate.
  It fails when no job or step inherits the workflow `RUSTFLAGS` unchanged; when
  the gate value differs; when the gate exports it before the refresh, after
  any Rust step, or more than once; when encoded flags are not cleared; when a
  later gate line changes Rust flags; or when a non-platform CI Rust command is
  missing after the export. Negative cases cover each rule.
- The `check-ironcrew` skill records the warning-denied CI environment for
  manually reproduced feature builds.
- Validation: `bash -n scripts/pre-push-check.sh`,
  `bun test scripts/tests/*.test.ts`, the Python repository-policy tests,
  skill validation, the registry check, and
  `RUSTFLAGS=-Dwarnings cargo build --no-default-features`. A temporary
  dead-code item that builds cleanly without the flag fails with it. The
  complete pre-push gate, now warning-denied, ran against PostgreSQL 17 and
  latest before the push; hosted CI is recorded on the pull request.
- Out of scope: `cargo clippy --all-targets --no-default-features` with
  `-Dwarnings` also reports dead code in `src/engine/human_input.rs`. CI does
  not run that combination, so it is not a parity gap.
