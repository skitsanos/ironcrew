# IC-017 — Durable SSE edge cases lack a separate-process gate

## Required outcome and acceptance

The separate-process PostgreSQL target proves retained cursor resume and
terminal replay through a peer. Malformed, cross-run, ahead-of-journal, pruned
cursor, explicit-gap, and incomplete-terminal fallback behavior remains covered
only by router or store tests. That leaves the HTTP status, cursor, and bounded
polling contract unproven across independent process-local registries.

Required outcome:

- start two real processes against disposable PostgreSQL 15 and exercise every
  documented malformed, cross-run, ahead, expired, and gap cursor outcome
  through the non-owner replica;
- force bounded retention/pruning so an expired cursor produces the documented
  explicit gap and terminal fallback without duplicates or silent data loss;
- preserve page/event byte limits, read deadlines, authentication, and
  `Cache-Control` behavior on every success and failure path;
- prove HITL prompt, choices, answers, secrets, and other prohibited payloads do
  not appear in the durable journal or error bodies; and
- record exact HTTP responses, event sequences, journal bounds, row counts, and
  cleanup while keeping real load-balancer behavior under IC-007.

Passing store-level cursor tests alone does not close this process-boundary gate.
