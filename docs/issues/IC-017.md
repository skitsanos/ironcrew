# IC-017 — Durable SSE edge cases lack a separate-process gate

## Outcome and validation

**Resolved locally on 2026-08-08.** The separate-process PostgreSQL target
previously proved retained cursor resume and terminal replay through a peer,
while malformed, cross-run, ahead-of-journal, pruned-cursor, explicit-gap, and
incomplete-terminal behavior remained below the process boundary.

The extended gate starts two real IronCrew processes against disposable
PostgreSQL 15.18. Replica A owns a provider-free run while non-owner replica B
serves the event stream and all cursor probes. The gate covers missing
authentication, malformed and non-ASCII values, zero and non-canonical
sequences, cross-run cursors, cursors ahead of the journal, and physically
expired cursors with exact HTTP status and body assertions. Success and failure
paths also assert the documented content type, cache policy, buffering header,
and authentication-first behavior.

A four-event per-run limit and 1 KiB event/page limits force deterministic
capacity eviction. The test records all seven original payloads, retained
bounds, byte usage, row counts, one explicit writer-backpressure gap, boundary
resume without duplicates, and then retention through the terminal sequence.
After retention, repeated reads return the same unnumbered incomplete terminal
fallback and bounded maintenance reduces journal usage to zero. A row-scoped
database barrier separately proves the 100 ms read deadline, exact non-cacheable
`503`, bounded live-stream closure after repeated timeouts, readiness confirmed
after lock release, and successful replay from a fresh request.

The gate scans every journal payload and error body for HITL prompts, choices,
answers, API tokens, idempotency material, and encryption-key material. Four
consecutive focused runs passed in 7.69, 7.76, 7.71, and 7.68 seconds. The final
complete separate-process target passed 5/5, and the complete PostgreSQL target
set passed 2/2 multi-replica HTTP tests, 44/44 store tests, and 5/5 process
tests. Schema, function, and replica-backend cleanup was verified before the
disposable database was removed.

This resolves the local process-boundary gate. At this issue's resolution,
Railway/OpenShift load-balancer routing was still assigned to IC-007; IC-007's
later deployed canaries closed that platform boundary. This page remains the
authoritative local-process receipt rather than duplicating the platform proof.
