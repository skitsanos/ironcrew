# IronCrew 4.0.1

IronCrew 4.0.1 carries the v4 functionality and
breaking changes described in the [v4 upgrade guide](v4.0.0.md). It retains the
PostgreSQL 17 minimum for the lifetime of IronCrew 4.x, checked usage receipts,
shared token budgets, construction evaluation, and bounded CLI/HTTP HITL smoke.

## Release recovery — IC-049

The `v4.0.0` tag was pushed after green release-PR CI, exact-main CI and full
local gates. A later CI run exposed a timing-sensitive acceptance assertion:
durable terminal run status was treated as a terminal-journal flush barrier.
The documented SSE contract correctly permits an unnumbered, explicitly
incomplete fallback while the numbered terminal append is pending.

Publication was cancelled before protected approval. No v4.0.0 GitHub release
or Docker image was published, and its immutable tag is retained unchanged.
Version 4.0.1 adds a bounded terminal-sequence barrier to the numbered-replay
test and regressions for pending appends and stalled reads. No production SSE
behavior or compatibility policy is changed.

## Upgrade

For users upgrading from v3, all [v4 breaking changes and migration steps](v4.0.0.md#breaking-changes-and-upgrade-checklist)
apply. Back up existing stores, drain active runs, upgrade PostgreSQL 15/16 to
17 or newer, and update consumers of the checked usage contract before rollout.

## Validation

The corrected source passed the full local Rust/repository/Lua/evaluation
checks, PostgreSQL 17.11 and 18.6 suite batches, short replica soak, and optimized
release build. The affected live test additionally passed 10 consecutive
repetitions per PostgreSQL major. See [IC-049](../issues/IC-049.md) for the
source/binary-bound evidence and limitations.

Clean pre-push/hook gates, exact-head platform CI and protected publication
receipts are recorded separately on the release pull request. The earlier
v4.0.0 and live Luna receipts retain their original source identities; this
patch does not claim new paid-provider or deployed acceptance.
