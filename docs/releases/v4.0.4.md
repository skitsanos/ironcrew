# IronCrew 4.0.4

IronCrew 4.0.4 makes the pre-push gate's temporary-directory isolation fail
closed and refreshes the dependency graph and release container base. It
preserves the Lua, CLI, HTTP and storage contracts, the PostgreSQL 17 floor
for IronCrew 4.x, and strict MCP 2026-07-28 support. The official MCP
specification index still selects that revision at release time.

## Validation isolation

- The pre-push gate validates its temporary-directory base before dependency
  refresh or tests. An explicit `TMPDIR` must be an existing writable absolute
  directory outside the checkout, with no `.env` entry in its resolved ancestry.
  An unsafe or unusable base fails without falling back to another location.
- Unset or empty `TMPDIR` uses `/tmp`. After admission, the gate creates one
  private directory and exports it as `TMPDIR`, `TEMP` and `TMP`, so subprocess
  temporary workspaces share the same safe ancestry. Cleanup removes that
  private directory while preserving the caller's base and existing files.
- Focused regressions cover invalid paths, ancestor `.env` entries, permission
  boundaries, consistent subprocess variables, early failure and scoped cleanup.
  This changes validation isolation; it does not change application `.env`
  loading, scrub unrelated inherited variables or replace disposable database
  admission.

## Dependencies and container runtime

- Updates rmcp to 3.7.0 and refreshes compatible transitive dependencies,
  including `ctutils` 0.4.5, `cc` 1.10.0 and `webpki-root-certs` 1.0.11.
  The chat UI uses the current stable Bun type definitions.
- Pins the tag-owned release image and matching workflow receipt input to
  Wolfi base index
  `sha256:f15fea2f49cb14dceaea491fcbde0d35e0c190126a744ac05a9838440d47d994`.
  The base refresh updates Brotli and Wolfi signing keys while retaining the
  required glibc, OpenSSL and CA runtime. Image assembly uses prebuilt release
  binaries and performs no moving package installation.

## Upgrade and dependency constraints

4.0.4 is a drop-in replacement for 4.0.3; source builds still require Rust
1.99.1. There is no storage migration or protocol fallback. For upgrades from
v3, follow the [v4 migration checklist](v4.0.0.md#breaking-changes-and-upgrade-checklist).

The current rmcp transport retains `sse-stream` 0.2.6 below 0.3 for public
transport type compatibility. Current upstream exact pins retain
`generic-array` 0.14.7 through `crypto-common` 0.1.7 and `matchit` 0.8.4 through
Axum 0.8.9. Release checks include incompatible direct updates, the newest
compatible lockfile graph and the current RustSec database; these constraints
are retained without audit suppressions.

## Release qualification

Release qualification requires the complete local pre-push gate: repository
policy, Rust formatting, all-target Clippy with denied warnings, all-target and
documentation tests, dependency audit, Lua construction and offline runtime
probes, mock-provider evaluation contracts, all five PostgreSQL suites on both
the floor and latest stable disposable databases, a bounded two-replica smoke,
and a locked optimized build. Exact commit results are recorded in the release
pull request and its CI. macOS and Windows platform results are hosted CI
evidence. Protected publication builds four platform archives and the signed
multi-architecture OCI archive and receipt.

These checks do not claim new live-provider effectiveness, production capacity,
execution failover or deployed-service acceptance.
