# IronCrew 4.0.3

IronCrew 4.0.3 fixes recovery prompt data isolation and refreshes the security
and toolchain dependencies. It preserves the Lua, CLI, HTTP and storage
contracts, the PostgreSQL 17 floor for IronCrew 4.x, and strict MCP 2026-07-28
support, which remains the latest published protocol revision at release time.

## Recovery and security

- [IC-052](../issues/IC-052.md): provider error diagnostics reach recovery
  handlers as literal data. Only configured templates are interpolated;
  diagnostic expressions cannot select runtime environment values or task
  results. Existing dependency evidence keeps priority within the prompt limit,
  including small budgets and UTF-8 boundaries.
- [IC-053](../issues/IC-053.md): updates the locked Rustls, WebPKI and root
  certificate dependencies to patched versions, with no audit suppressions.
- Tokio 1.54.1 replaces the withdrawn 1.54.0 dependency and includes the
  fix for RUSTSEC-2026-0384 / GHSA-5wjr-9356-4wc8.

## Toolchain and validation

- [IC-054](../issues/IC-054.md): source builds require Rust 1.99.1. The
  toolchain, official builder image, workflow actions and policy expectations
  are aligned. Managed Cargo and chat UI dependencies are refreshed.
- [IC-017](../issues/IC-017.md) follow-up: the replica acceptance test bounds
  SSE reconnect attempts after a journal timeout and tests the retry helper.
  This improves the acceptance harness without changing production SSE behavior.
- API contention regressions use deterministic synchronization and verify
  cleanup before asserting admission capacity.
- The pre-push gate checks for `psql` before dependency refresh or compilation,
  so missing PostgreSQL client tooling fails early.

## Upgrade and dependency constraints

4.0.3 is a drop-in replacement for 4.0.2; source builds require Rust 1.99.1.
For upgrades from v3, follow the [v4 migration checklist](v4.0.0.md#breaking-changes-and-upgrade-checklist).

The current dependency graph retains `sse-stream` 0.2.6 below 0.3 for rmcp's
public transport type compatibility. Upstream exact pins retain
`generic-array` 0.14.7 through `crypto-common` 0.1.7 and `matchit` 0.8.4 through
Axum 0.8.9. The release refresh checks direct dependencies, incompatible
updates, the newest compatible lockfile graph and the current RustSec database.

## Release qualification

Release qualification requires the complete local pre-push gate: repository
policy, Rust formatting, all-target Clippy with denied warnings, all-target and
documentation tests, dependency audit, Lua construction and offline runtime
probes, mock-provider evaluation contracts, all five PostgreSQL suites on both
the floor and latest stable disposable databases, a bounded two-replica smoke,
and a locked optimized build. Exact commit results are recorded in the release
pull request and its CI. macOS and Windows platform results are hosted CI
evidence. The release workflow builds four platform archives and the signed
multi-architecture OCI archive and receipt through protected publication.

These checks do not claim new live-provider effectiveness, production capacity,
execution failover, or deployed-service acceptance.
